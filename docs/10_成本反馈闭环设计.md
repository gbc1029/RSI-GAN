# 成本反馈闭环设计（cost feedback loop）

> 本文是 `docs/cost_tem.md` 初步设计的**框架级整合方案**：在仓库现状
> （测量已基本闭环、反馈与控制缺失）之上，给出分层架构、信息流、目标函数与
> 分阶段路线。不落到代码级；落点只指到既有机制（文件/事件/投影）为止。
> 术语沿用 cost_tem.md：cost = token（主）+ 时间（次）+ 工具调用次数（再次）。

---

## 0. 现状盘点：测量已有，反馈缺失

**已经存在的测量/记账面（本设计的地基）：**

| 数据 | 位置 | 粒度 |
|---|---|---|
| 每次 LLM 调用的 prompt/completion/total tokens、延迟、状态、reasoning_effort | `logs/events.jsonl` `llm_call`（proxy 审计，三角色全部经过） | 逐调用，role + scope（task=`genid`，role=`outer`） |
| 每轮 reasoning_tokens、finish_reason；每次工具调用及输出 | 会话轨迹 JSONL（`trajectory/outer_*/**`） | 逐轮 / 逐工具调用 |
| task 子进程每代成本 | `_llm_cost_for_gen` → `NodeValue.cost_tokens/cost_wallclock_s` → `scores.jsonl` / `packet.json` | 每 genid |
| 工具调用预算 | `loop.plan/evaluate/self_improve_max_tool_calls`（per-seat），task 子进程默认 40 未传参（B21） | 每会话 |
| 时间预算 | `question_timeout_s`（task）、per-call timeout C1、proxy/client 超时链 | 每题 / 每调用 |
| 反抑制 | `tool_repeat_limit`（anti-thrash）、C2 输出上限、知识物化上限 | 每会话 / 每物化 |
| 选择面钩子 | UCB `tree.cost_penalty`（默认 0，实测因旧账本缺口长期为 0 项）、`RewardPacket.numeric.cost_tokens` | 每节点 |
| 预留死键 | `loop.yaml` `cost.token_budget_per_gen` / `cost.record_usage`（B21/G3 待激活） | — |

**缺失的环节（本设计要补的）：**

1. **感知**：没有任何 agent 能看到成本数字。成本只在 `events.jsonl` / `scores.jsonl` 里躺着，是离线分析原料，不是决策输入。
2. **归因粒度**：role 会话在审计里只到 `outer` 级——无法回答"这次 plan 会话花了多少"。逐会话归因是反馈的前提。
3. **控制**：除工具调用次数与超时外，没有 token/时间预算键；`agent/llm.py` 的 `USAGE_HOOKS` 注册机制空挂。
4. **上下文管理**：上下文组装是固定的（instruction 拼装 + C2 输出上限 + `read_trajectory` 的 6000 字符截断）。roles 能动的只有工具与 design 键，没有"策略性取舍上下文"的接口。
5. **目标**：优化目标只有 score（stagnation / advantage / UCB）；`cost_penalty` 关闭。成绩—成本没有均衡点。

结论：本设计 = 在已有账本之上补齐 **感知 → 决策 → 执行 → 再测量** 的回路，
让成本成为 (a) 提示/反馈面 (b) design 面 (c) 选择面上的一等信号。

## 1. 设计原则（与仓库既有约定对齐）

1. **单一事实源**。成本账本只从 proxy 审计 + 会话轨迹聚合得出；所有注入面、
   receipt 字段、meter 工具读同一个聚合器。禁止任何第二套计数（对齐
   `_llm_cost_for_gen` 的 "single source" 约定）。agent 自报的成本一律不作数。
2. **投影式可见（default-deny）**。成本信息进入任何决策面都必须走命名投影
   （与 `_EVALUATOR_META_KEYS` / `build_diff_summary` 同一模式）：新字段默认
   不可见，开放要显式列出。防止成本数字变成新的说服/操纵通道（B29 的成本版）。
3. **可见性复用，不立第二套权限面**。成本数据按 scope（genid/outer/seat）切片，
   切片后的可见集合**沿用 `AccessContext.trajectory_genids` 的同一语义**；
   自己会话的账单永远对自己可见。task 的可见面保持最小（见 §4）。
4. **软约束优先，硬钳制兜底**。预算先以"对账单 + 余量"的形式反馈，让 roles
   自己调；框架只在消费点做区间钳制。硬截断只对可安全截断的资源生效
   （知识物化、read 输出、工具调用上限），并且必须留痕——evaluation seat 的
   教训直接适用：预算不能饿死必需动作，否则毁掉评分信号本身。
5. **成本永远与质量同表**。单独的成本数字没有意义，且会诱发"省钱退化"
   （reward hacking 的成本版：少答题、少调用）。每个成本可见面都伴随
   score / 相对基线；均衡目标显式化为**单位成本的质量**，不是最低成本。
6. **进化面收敛**。成本相关的新可进化物一律落进现有两类通道：
   `always-on → gan/tools/`，`opt-in → gan/components/`（registry + identity +
   heal + preflight 全链路复用），加 design 键（含保留键）。**不新增第四类
   可进化物**——独立"上下文管理器"必须统一到这两类通道上（§5.2）。
7. **分阶段激活，先反馈后惩罚**。成本信号在进入选择压力（UCB）之前，必须先
   经过至少一个阶段的"只反馈不惩罚"观察期——坏信号（噪声、None、伪造）一旦
   进入选择面就难以摘除。

## 2. 分层架构

```
L4 目标层     UCB cost_penalty / 效用=score−λ·cost        （选择压力，最后激活）
L3 控制层     design 保留键族 ｜ 上下文管理组件 ｜ 行为软约束   （可进化）
L2 反馈层     成本对账单注入 ｜ meter 工具（实时）          （框架注入 + opt-in 工具）
L1 聚合层     成本聚合器 + 命名投影 + per-session 归因      （冻结，框架所有）
L0 账本层     proxy 审计 + 会话轨迹 + harness 计时          （已有，微扩）
```

读法：L0/L1 是**框架私有**（不可被 roles 修改、不可绕过）；L2/L3/L4 是**接口面**
（L2 里框架注入的部分固定，工具部分 opt-in；L3/L4 按 §7 分阶段放开进化空间）。

### 2.1 L0 账本层（微扩，不改进化面）

- **逐会话归因**：role 会话的 LLM 调用审计需要细化到 seat 级
  （`plan` / `evaluate` / `self_improve`，含 patch-retry 轮次的从属关系），
  使"每个会话花了多少"可从账本直接回答。task 侧已有 `genid` 粒度，不动。
- **会话轨迹补字段**：`output` 行目前只有 `reasoning_tokens`；补 prompt/completion
  总量（或由聚合器从审计关联），使轨迹自足、可离线重算。
- 既有口径保持：未记录的成本必须是 None，不是 0（伪造的 0 会污染所有下游比值）。

### 2.2 L1 聚合/投影层（新增，冻结）

一个成本聚合器（即 G3 规划的 usage aggregation 的完整形态），产出：

1. **per-session 成本记录**（每会话结束落盘，进 run 级小文件 + events，
   与 `patch_receipt.json` 同级的 "small evidence" 习惯）：
   tokens（prompt/completion/reasoning 分列）、调用数、工具调用数、
   墙钟时长、超限/钳制事件。
2. **命名投影**：供 L2/L4 消费的白名单字段族（对账单、receipt.budget、
   packet.numeric 的成本项），与现有投影管线同构。
3. **口径归一**：聚合器是唯一允许计算"占比/比值/与父代差值"的地方——
   相对值的定义集中一处，防止各注入面各算各的（数字漂移是最廉价的欺骗）。

### 2.3 L2 反馈/感知层（新增；注入固定，仪表可进化）

注入分两档，回答 cost_tem 的"注入精度"问题——**推送做历史对账，拉取做实时**：

- **成本对账单（cost statement，框架注入，每会话首条消息一节）**：
  - `plan` 会话：本 genid 即将消耗的预算（生效键值）+ 父代链 task 成本
    （经 L1 归一化策略换算的相对值，见 §4）+ 自己上一轮 plan 会话成本。
  - `evaluate` 会话：本代 task 成本摘要（作为**过程事实**：重试次数、超长
    reasoning、超时——e 判断过程合理性正需要它）+ 自己上轮成本。
  - `self_improve`（p/e 各自）：本 outer 全部自己会话的成本 × 对应 score/digest
    对齐（这是"成本—成绩"联合反思的主材料）。
  - 内容形态：聚合统计（会话级汇总 + 按工具类/阶段分桶 + Top-N 异常调用提示），
    **不逐调用**；逐调明细留在轨迹里，由 read 工具按需索引。
- **meter 工具（实时，opt-in 组件）**：会话中按需拉取当前已用量/余量。
  理由：逐 turn 推送会自我指涉地烧 token 且污染消息流；"按需拉取"让实时性
  成为能力而不是税。

### 2.4 L3 控制层（新增，可进化）——三条途径，详见 §5

1. design **保留键族**（成本参数直接下沉为 design 键）；
2. **上下文管理**（统一接口：浅层键选择 + 深层组件实现，select_trajectory 为首例）；
3. **行为软约束**（对账单中的提示语 + evaluator 以 issue 通道提成本类问题，
   planner 以结构化 stance 回应——复用现有 5 类 stance，不需要新通道）。

### 2.5 L4 目标层（分阶段激活）

- 效用形状（建议）：`效用 = score − λ · normalized_cost`，λ 在 `loop.yaml`
  （框架层，非进化面）。先沿用现成的 UCB `cost_penalty` 语义（线性惩罚），
  "达标前提下最小化成本"的门限型目标留待观察后再议。
- `normalized_cost` 的可比性是 **L1 聚合器里的可插拔归一化策略**，架构不绑定
  任何具体采样机制（`sampling.anchor_k` 是初步实验的折中，后续可能取消，
  不作为设计核心）：
  - **默认策略（无采样假设）**：per-question 口径（成本/题，而非成本/代）+
    滑窗分布对比——本代 vs 近 W 代的 per-question 成本分布（中位数/IQR）。
    样本构成跨代变化时，按题归一自然吸收；不同题天然难易不同的问题，
    由"与自身窗口分布比"而非"与别的题比"来消解。
  - **预算口径（绝对锚，永不失效）**：占生效预算的百分比——跨采样机制稳定，
    是对账单和余量计算的主口径。
  - **配对策略（可选）**：仅当采样器显式声明提供跨代同题配对时启用同题差分；
    策略声明自己的可比性假设，假设不成立即退回默认。anchor 取消 =
    换一个策略字段值，架构零改动。
  - λ 的定义同样挂在归一化策略上；Phase E 前用离线历史拟合。
- 预算执行情况（`budget_exhausted`、钳制事件）作为 receipt 事实进反馈面，
  不直接进惩罚项。

## 3. 对 cost_tem.md 四个方案的逐条落点

| cost_tem 方案 | 落点 | 修正/取舍 |
|---|---|---|
| 成本参数下沉为 design 键 | 采纳：**保留键族**（框架预声明、框架消费、消费点钳制，不受"键必须有消费者"检查约束——与 `loop.yaml cost.*` 预留注记同一语义） | 不开放 num_samples/model（同意）；**reasoning_effort 建议开放为键**：它是现成的成本杠杆、models.yaml 契约已存在；但 design 键只能在框架给出的允许枚举内取值且消费点校验（值域归框架），model 本身仍由 models.yaml 唯一裁决 |
| select_trajectory 优化 | 并入"上下文管理"作为**第一个实例**：slice 模式 = read_trajectory 先返回索引、按需取详情 | 索引由**框架预构建**（结构化：turn/工具/阶段三级 + 字节与 token 估计 + 元数据），不做语义索引（无 embedding，且语义匹配会把"不可进化的设计"伪装成能力）；roles 进化的是**选择函数**（组件），不是索引构建。权限过滤决定"可选宇宙"，选择函数只能在宇宙内做子集——只能缩小，不能扩大 |
| 直接文本反馈 | 采纳为 **Phase B 基座**（最先落地）：对账单注入 + e 经 issue 通道提成本问题 | inner 侧"经 e 的 eval-point"即 `report_issue` 现有通道，不建新通道；outer 侧注入 self-improve 的 recent payload |
| 独立"上下文管理项" | **不独立成第四类可进化物**：统一为"框架侧组装 seam + 浅层 design 键（选择预设）+ 深层组件（实现策略）" | 自由设计/约束设计由此变成**同一表面的两个深度**：约束 = 只用配置组合框架原语；自由 = 经 deep 通道重写组件源码（edit_source，走既有 gating）。分层设计的浅/深双通道即仓库现行的 opt-in 组件模型 |
| 延后：成本进 parent 选择 | 同意延后，且更准确地说：**p/e 目前是 single-chain、没有 parent 选择器**，成本注入调度没有挂点 | task 树的 `cost_penalty` 就是第一阶段的目标层；p/e 侧等调度器演进 |

## 4. 信息流矩阵（谁在哪个会话看到什么）

对齐 AGENTS.md 的隔离原则：**只看自己有权管理的面 + 当前会话**。

| 会话 | 可见成本 | 不可见 |
|---|---|---|
| planner / plan | 本代预算生效值；父代 task 成本（经归一化策略的相对值）；自己上轮 plan 成本 | evaluator 的内部成本明细（只有全体汇总档，若投影开放） |
| evaluator / evaluate | 本代 task 成本摘要（过程事实）；自己上轮成本 | planner 会话成本明细（防其成为说服面） |
| p/e / self_improve | 自己本 outer 全部会话成本 × score/digest 对齐 | 对方角色的成本 |
| task / task | 当前会话实时余量（若安装 meter 组件）；生效的预算键值 | 全局账本（t 的读面本来就是 none） |

**时间维度**：注入默认 = 上一代 + 本 outer 窗口（I_max 个 inner）聚合；
更早历史走离线分析（`scripts/local/gan_scores_extract.py` 加成本列，零风险）；
更深回看经 read 工具，且受 `trajectory_genids` 同一可见集约束（原则 3）。

**粒度决策（cost_tem 的开放问题，明确回答）**：

- 传递粒度：**聚合，不逐调用**。会话级汇总 + 分桶 + Top-N 异常提示；
  逐调明细已存在于轨迹（audit 面），复制进提示面只有成本没有收益。
- 注入精度：**每会话首条注入一次（对账）+ opt-in 工具拉取（实时）**。
  逐 turn 实时注入被否决：烧 token 且污染消息流（自指问题）。
- 相对值 vs 绝对值：**两者都给，相对值为主信号**。绝对 token 数跨模型/跨任务
  不可比；给"占预算百分比 + 经归一化策略的窗口相对值 + 绝对数"三元组。
- 口径：token（prompt/completion/reasoning 分列——reasoning 是推理模型的成本
  大头，轨迹里已单列，注入面必须保留这一列）、墙钟次之、工具调用数再次。

## 5. 控制层三条途径的设计

### 5.1 保留键族（成本参数）

- 每角色的 `cost.*` 键族，声明进框架 schema（不走 `add_config_key`，
  因此天然免"必须有消费者"检查——保留键语义正是为此预留的）：
  task：per-question token 预算、工具调用上限、知识物化上限、思考强度、
  轨迹读取模式（default/slice）；planner：plan 会话预算、patch 重试上限；
  evaluator：evaluate 预算（盲/揭示两相分开——沿用现有 per-phase 预算的教训）。
- **归位规则**：谁的键进谁的 design。task 预算键在 task design（planner 经
  shallow 通道改）；p/e 自己的预算键在各自 self-design（self-improve 改）。
  这一条直接产生"**预算锦标赛**"选择压力：省预算且成绩不掉的设计被保留，
  同时 p 对 t 的成本决策与 e 对自身的成本决策都内化为其设计责任。
- **消费点钳制**：每个键声明允许区间（框架层给定，非进化面），消费点 clamp
  并留痕（钳制事件进账本）。软预算超限先注入预算警告 turn（与现有
  budget-exhausted turn 同形态），硬钳制只用于可安全截断的资源。
- B21 顺路接线：task 子进程的 `max_tool_calls` 与 per-question 预算一并
  传参（同一链路，避免两次动它——§7 遗留账已有此建议）。

### 5.2 上下文管理（统一接口）

#### 5.2.0 两种实现位置：tools 框架内 vs 独立模块

先记录两个**结构性事实**（已核实 `agent/llm_withtools.py` 的会话循环）：

- **消息历史只增不减**：每轮 LLM 调用的完整历史（含所有过往工具输出全文）
  原样进入下一轮上下文；C2 的 16k 上限只约束单次工具输出，不约束留存。
- **固定开销逐轮重发**：tool-use prompt（`system_msg`）每轮拼接进新消息，
  即 T 轮会话里它在上下文中出现 T 次；指令面（对账单、预算横幅）在会话
  开始前装配，工具调用发生在装配之后。

这两条决定了 tools 框架内 CM 的能力边界。

> **术语约定（本文用"会话内/装配时"，不用"环内/环外"）**：会话的**工具循环**
> （`chat_with_agent` 的 while 循环；一轮 = 一次 LLM 调用 + 其触发的工具执行
> + 结果进历史）比仓库的"内循环/外循环"（inner/outer，代际调度）**低一层**。
> 为避免混淆，本文定义：
> - **会话内（agent 驱动）**：发生在循环体内、由 agent 的工具调用触发的事件
>   ——每次消耗一个 LLM turn（往返）、只能向历史**追加**、留痕天然完整
>   （`tool_call`/`tool_output` 行）；
> - **装配时（框架驱动）**：发生在每轮 LLM 调用前的**视图装配点（seam）**
>   与会话边界上的事件——选择逻辑是代码、零 LLM 成本、能改写"实际发送的
>   视图"、必须靠装配事件留痕（没有天然的 tool_call 记录）。
> 两者的分界线就是 seam：**历史进入 LLM 之前的最后一站**。

**方案 T——CM 呈现为一组工具，agent 在会话内调用**：

- 机制：`ctx_index` / `ctx_fetch(block)` / `ctx_budget`（meter）/
  scratchpad（跨轮工作笔记）等工具；agent 每次调用，输出进消息历史，
  下一轮 LLM 看见；选择逻辑由 LLM 在会话内完成。
- 能管：**进入什么**（拉取哪些块、以什么形态——全文/索引/摘要占位）、
  当前余量（meter 拉取）、自维护的工作记忆（scratchpad）。
- 不能管（结构性缺位，非工程量问题）：
  1. **留下什么**——历史只增不减，agent 无法驱逐/压缩已进入的内容
     （它连自己的历史都改不了）；会话越长，成本下限越高，"控制消耗"
     只能完成"少拉取"这一半；
  2. **固定开销**——逐轮重发的 tool-use prompt、装配在会话前的指令面，
     工具碰不到；
  3. **选择本身的成本**——会话内选择 = 每次拉取一个 LLM turn（往返），
     大块"按需详情"很贵，且选择逻辑是 LLM 调用而非代码，运行时成本高
     且不确定（可能把省下的 token 吃回去）；
  4. **预算执行点**——软预算检查、超限警告 turn、硬截断都需要框架在
     每轮循环内执行，不能依赖 agent 自觉调用工具。

**方案 M——CM 是会话循环内的框架拦截点（独立模块）**：

- 机制：每轮 LLM 调用前，框架执行 `view = CM(state)`；state = 任务、
  当前步骤、历史、可用块、工具输出、预算、已用成本——全部先经可见范围
  筛选 + 脱敏（cost_tem 第 3 条约定），CM 权限上完全可见；
  返回**实际发送给 LLM 的视图**（可压缩历史、选块、注入横幅、替换摘要占位）。
  policy = agent 写的组件（deep 通道重写），由框架托管执行；冻结默认策略
  （passthrough）兜底。
- 能管：T 的 1–4 全部——驱逐/压缩/占位（真正控制"留下什么"）、固定开销
  治理（tool-prompt 去重、指令装配）、装配时选择零 LLM 成本（选择逻辑是代码）、
  每轮预算检查点天然挂点。
- 代价/风险（方案 M 的新增复杂度所在）：
  1. **审计语义变化（最大项）**——轨迹必须双记：原始记录（audit 面，现有
     管线不动）+ 每轮视图装配摘要（丢弃/压缩了什么、多大、触发策略）。
     否则 `read_trajectory` 会展示 agent 实际没看过的内容，evaluator 的
     "过程事实"判断失真，resume 重放不闭合；
  2. **失败语义**——policy 崩溃不得毁会话：fail-open 回退 passthrough +
     响亮事件；静默丢内容必须留装配事件；
  3. **执行面扩大**——agent 写的代码被框架**每轮自动执行**（而不只是被
     调用时执行），不可信代码的运行时机变多，AST 策略/preflight 照旧但
     调用面变大；
  4. **演进面归属**——若做成新的可进化物类型，要复制 registry/heal/
     preflight 一整套；必须复用 components 通道（CM 只是"被框架调用的
     组件"，不是第四类东西）；
  5. **确定性**——policy 版本随 design 逐代固定（现有 design 继承天然
     提供）；同代内 policy 若带跨轮内部状态，须进 checkpoint 或声明无状态。

**对比小结**：

| 维度 | 方案 T（tools 内） | 方案 M（独立 seam） |
|---|---|---|
| 控制"进入什么" | ✅（agent 会话内选择） | ✅（policy 代码 + agent 皆可） |
| 控制"留下什么"（驱逐/压缩） | ❌ 结构性不可能 | ✅ |
| 固定开销治理 | ❌ | ✅ |
| 选择逻辑的运行成本 | 每次 LLM turn | 代码执行（零 LLM） |
| 预算执行点 | ❌（靠 agent 自觉） | ✅（框架每轮检查） |
| agent 当前语境用于选择 | ✅（最强项） | 弱（policy 代码看不到 LLM 的隐式意图） |
| 审计 | 天然完整（显式 tool_call） | 需双记（原始 + 装配摘要） |
| 新增机制 | 几乎为零 | seam + 双记 + fail-open + policy 托管 |

**采纳形态：seam 三段流水线上的"三分"权威架构，一次性实现到位**

方案 T 与 M 不是二选一，而是**同一个 seam 的两个输入端**。CM = 会话循环内
每轮 LLM 调用前的**唯一装配点**（现 msg 组装处；task 与 roles 共用同一
seam），内部是一条三段流水线：

```
冻结前置段（每轮必跑） → policy 段（可进化） → 冻结后置段（每轮必跑）
```

**频率分配：跟着不变性走（CM 不是会话前置）**

流水线**每轮 LLM 调用前都执行**。会话前置（每会话一次）的只有三类动作，
共同判据是**材料在会话内不变**：

| 频率 | 对象 | 判据 |
|---|---|---|
| 每会话一次 | 宇宙初始化（toolset + 生效预算键）、首轮对账单、轨迹索引预构建 | 材料会话内**不变**（轨迹先归档后评估、design 逐代固定） |
| 每轮 | 预算检查点、固定开销治理、policy 视图装配、不变量执行 | 状态**单调变化**（历史只增、预算只减、新块逐轮进入）；历史进入 LLM 前的最后一站是唯一改写点——错过即成事实 |
| 按需（会话内拉取） | `index` / `fetch` / meter / `pin` / scratchpad | 相关性**取决于 agent 当前语境**（cost_tem 的 query-match 缺陷只有 agent 能解） |

若把 CM 做成会话级前置：它只能改写初始指令，管不住逐轮重发的历史——
而历史重发正是成本主项；且驱逐/压缩的对象（工具输出等新块）在会话开始时
根本不存在。方案 M 的核心价值天然是每轮的。

**分一：契约层（冻结）——seam 位置、state/view 契约、不变量**

- state（输入，schema 带版本号）：任务、当前步骤、消息历史记录、可用块
  （本轮工具输出 / 轨迹索引 / 知识笔记 / scratchpad）、生效预算键、账本
  已用量、role/seat/genid——全部先经可见范围筛选 + 脱敏（cost_tem 第 3 条）。
- view（输出）：实际发送给 LLM 的上下文。只能**从块**做选择、重排、占位
  替换；不能造新内容，占位必须引用块 id（可溯源）。
- 不变量（后置段强制，policy 结构上无法违反）：
  1. **可见宇宙只能缩小**——redaction 发生在 seam 之前，policy 不能扩大；
  2. **pinned 块不可丢**——最近 K 轮与当前问题默认 pin（K 是带框架下限的键）；
  3. **policy 是纯代码**：无 LLM、无网络、有执行预算（连续超时按 C1 的
     wedge breaker 同款语义：本会话禁用该 policy）；
  4. **每轮产生 `cm_view` 装配事件**：丢了什么（块 id）、多大、哪条规则
     ——只有引用与尺寸、无内容，不新增泄漏通道。这是**双记审计**的落点：
     原始记录（现有管线不动）+ 每轮装配摘要（cm_view），read 工具两者
     都能渲染——`read_trajectory` 永远不再展示 agent 实际没看过的内容。
- 三类**装配时固定行为**放在前置段（每轮必跑、冻结代码、不是 policy）：
  预算检查点（账本 vs 生效键 → 警告 turn / 钳制）、固定开销治理
  （tool-use prompt 去重）、横幅注入（成本对账单 / 预算警告）。这三件
  是 tools 框架原理上做不到的事，由框架直接拥有，不开放给 policy。

**分二：词汇层（冻结）——原语集合，双形态暴露**

- 为什么冻结：装配事件要引用操作名 → 审计词汇必须封闭；跨代 policy 要
  可比较；cost_tem 要求"足够广的原语保证进化空间"——**广度放进集合
  设计，不放进可变性**。
- 集合：`index`（可用块枚举+元数据：来源/尺寸/token 估计/类型）、`fetch`
  （物化：全文/首尾/占位）、`drop`（驱逐→占位）、`compact`（机械压缩：
  摘录合并/首尾/模板填充——不含 LLM 摘要）、`pin`/`unpin`、`order`、
  `budget_query`（账本查询，与 meter 同源）、`peek`（policy 只读内容）、
  `note`（scratchpad）、`view_state`（agent 知情权）——**完整初始设计
  （签名/约束/工具映射/键）见 §5.2.3**。`dedup`/`banner` 是前置段固定
  行为（键控参数），不是可调用原语，见下。
- 双形态：
  - **会话内（agent 面）**：以工具暴露 `index` / `fetch` / `budget_query` /
    `pin`（保留申请）/ `scratchpad`——agent 的拉取决定"宇宙里有什么"
    （新块进历史记录），其当前语境用于选择（cost_tem 指出的 query-match
    缺陷由此化解）；
  - **装配时（policy 面）**：全集合可调用——`drop` / `compact` / `order`
    等"留下什么"的决定权只在 policy / 后置段，因为只有框架能在历史进入
    LLM 之前改写它；`drop` 不设 agent 工具（agent 调用的"丢弃"输出本身
    会进历史，驱逐必须发生在视图层）。
- 组合关系：agent 侧动作改变块宇宙，policy 每轮决定视图；两者作用于同一
  宇宙，冲突由不变量裁决（pin 是 agent 的保留申请，policy 必须尊重）。

**分三：决策层（可进化）——policy 组件 + 会话内 agent pull**

- policy 的三重身份（全部对齐既有约定）：
  1. **呈现为组件**：注册进 per-role registry（`name==stem==tool_info`
     契约照旧）、可 `list_components`、可选、可深度重写——"以 tools 呈现"
     的进化面约定不破，唯一扩展是**调用者**从"仅 agent"扩展为
     "agent 或框架"；
  2. **谁的 policy 改谁的**：task 的 CM policy 在 task 组件树（planner 经
     shallow/deep 通道改），p/e 各自在 self-improve 改自己的——预算
     锦标赛同样作用于上下文策略（省上下文且成绩不掉者被保留）；
  3. **深浅双通道 = cost_tem 的约束/自由设计**：浅 = design 键选预设
     （passthrough / slice / 压缩档）或声明式原语组合；深 = deep 通道
     重写 policy 源码（`edit_source`，既有 gating 不变）。
- 失败/退出语义（一次性实现）：op 级违规 → 后置段拒绝该 op +
  `cm_violation` 事件；连续违规 → 本会话禁用该 policy；policy 异常 →
  fail-open passthrough + 事件；policy 声明有状态/无状态（默认无状态；
  有状态须把 scratch 并入会话记录，保证 resume 可重放）。
- 默认 policy = passthrough（恒等视图）。这是**安全默认值，不是未实现的
  功能**：压缩是否启用是 design 键的激活状态，机制本身一次到位。

**一次性实现到位**：seam 三段流水线、原语全集及其双形态暴露、policy 槽、
双记审计、fail-open、三类装配时固定行为、read_trajectory 的 slice 消费端
——CM 的全部机制一个阶段落地，不再拆"先 T 后 M"两步。（CM 依赖的账本/
聚合与预算键是它的数据来源前置，属 A/C 层，不是 CM 的分期。）

**不全用 T 的理由**：1/2/4（留存、固定开销、预算执行点）是能力缺位——
只增历史 + 逐轮重发是结构性成本下限，长会话（task 多题、p/e 的 patch
重试链）下"控制消耗"只能完成一半。**不全用 M 的理由**：agent 的当前
语境是最便宜且最准的选择信号（cost_tem 自己指出 query-match 缺陷，解法
恰是保留会话内 pull）；且 M 的审计/失败语义复杂度要求把装配时自动执行面压到
最小——这正是三分架构把"自动执行"收缩为前置段三类固定行为的原因。

#### 5.2.1 select_trajectory：CM 在轨迹块上的首例（结合方式）

select_trajectory 不是与 CM 并列的机制，而是**同一套三分架构在"轨迹块"
这一来源上的实例化**——它的三个环节各归其位：

| 环节 | 位置/频率 | 内容 |
|---|---|---|
| 索引构建 | 装配时·每会话一次 | 轨迹**先归档后评估**、会话内不变 → 建一次供整会话用。框架预建结构化索引：turn/工具/段三级 + 元数据（来源、尺寸、token 估计、工具名、异常标记）；只含可见块（`trajectory_genids` ∩ 已脱敏）。**索引本身就是 `index` 原语在轨迹上的输出** |
| 索引阅读 + 按需详情 | 会话内·agent 决策（每次一个 turn） | slice 模式下 read_trajectory 先返回索引，agent 挑重点 `fetch` 详情——**当前语境指导选择**，cost_tem 的 query-match 缺陷由此化解；`max_chars` 自然延伸为 fetch 的形态参数 |
| 详情的后续保留/压缩 | 装配时·每轮 policy | agent 已消化的详情在后续轮被 policy 降为占位（`cm_view` 留痕）。**"拉取进宇宙"是会话内的事，"留在视图里"是装配时的事** |

要点：

- **权限统一**：可见范围筛选 + 脱敏都发生在索引构建**之前**，索引只含
  可见块；选择函数只能在宇宙内做子集——只能缩小、不能扩大（§3 的并集
  表述在此闭合）。
- **成本闭环**：索引是小而稳定的块；每次详情拉取是一个 turn（会话内成本）；
  拉来的详情后来是否被压缩是装配时决策（`cm_view` 可查）。三者全部入账本
  → "会话内拉取的 turn/token 开销"成为 policy 进化的直接评价指标。
- **回答 cost_tem "索引是否提前建立"**：**索引提前建**（不变材料，框架供，
  小而稳定）；**选择逻辑由 roles 进化**（组件，深浅双通道；regex/硬条件/
  经验规则沉淀到知识库跨代复用）。对"单次 read 可及数据量不足以支撑复杂
  筛选"的回答：正因如此筛选必须分层——复杂逻辑不复刻索引，只消费索引。
- **memRL 近似**：哪些索引模式值得拉、哪些详情消化后即可弃——这类经验
  规则写进组件并沉淀到知识库（pull-based 数据载体：按"任务是否成功/成本
  是否超标"给笔记打标）；真正的 RL 式记忆加权等数据量起来再说。

#### 5.2.2 task 侧同构

per-question 上下文（知识检索策略、工具输出预算键控、跨题工作笔记）走同一
组件/键通道，不另起炉灶；task 的长会话（多题连跑）是方案 M 装配时压缩的
首要受益者，也是其风险最大的场景（压缩可能丢掉解题必需线索），因此 task 侧
的 policy 开放排在 p/e 之后。

#### 5.2.3 CM 原语与会话内工具初始设计

**块模型（原语的作用对象）**：

- **宇宙（universe）**：本会话所有已物化块，**只增不减**；每块有稳定
  `block_id`、`kind`、来源、字符数、token 估计、创建轮次、标志位
  （pinned / dropped / compacted）。
- **视图（view）**：本轮实际发送的有序 `(block_ref, form)` 列表；
  `form ∈ full / head_tail / excerpt / placeholder / template`。
- **派生块**：`compact` 的产物，id 形如 `derived:<op>:<n>`，**引用源块**
  （可溯源）。
- `kind`：`turn_output`（历史轮文本）/ `tool_output` / `traj_seg`（轨迹段，
  来自预建索引）/ `kb_note` / `note`（scratchpad）/ `boundary`（题界标记）/
  `derived`。
- 占位渲染（冻结模板）：`[block <id> omitted: <N> chars, kind=<k>, reason=<rule>]`。

**原语全集**（冻结核心，`gan/framework/cm/`；"面"= 谁可调用）：

| 原语 | 语义级签名 | 语义与约束 | 面 |
|---|---|---|---|
| `index` | `index(source, filter) → descriptors[]` | 枚举块元数据（id/kind/来源/chars/token_est/flags），**不含内容**；source ∈ history\|turn\|trajectory\|knowledge\|notes\|all；条目上限（镜像 `list_dir` 的 200） | 双侧：agent 工具 `ctx_index` + policy |
| `budget_query` | `budget_query() → usage vs budget` | 读账本（L1 同源）：tokens（分列 reasoning）/调用数/工具数/时长 → 余量+占比；meter 与它同一实现 | 双侧：agent 工具 `ctx_budget` + policy |
| `peek` | `peek(ref) → content(cap)` | 只读块内容（policy 决策输入；上限对齐 C2）。agent 侧不需要：已物化内容本就在历史里 | 仅 policy |
| `fetch` | `fetch(ref, form) → new_block` | 把块内容物化为**新块**进历史（下一轮可见）；form ∈ full/head_tail/range。对已压缩/占位块再 fetch 合法——内容本会话内可见过，不扩大权限宇宙，只是花钱 | 双侧：agent 工具 `ctx_fetch` + policy |
| `pin`/`unpin` | `pin(ref, note?)` | 保留申请：agent 侧=申请（**policy 必须尊重**）；policy 侧=决定。最近 K 轮默认 pin（K 走键，框架有下限） | 双侧：agent 工具 `ctx_pin` + policy |
| `drop` | `drop(ref, rule)` | 视图移除 → 占位（id+尺寸+规则）。≡ `substitute(ref, placeholder)` 的命名形式（独立命名为了 cm_view 语义清晰） | **仅 policy** |
| `compact` | `compact(refs, strategy) → derived_block` | 机械压缩：`excerpt`/`first_last`/`merge`/`template`（冻结模板填元数据+关键行）——**不含 LLM 摘要** | 仅 policy |
| `substitute` | `substitute(ref, form)` | 原位改形态（full→head_tail→placeholder），不增删 | 仅 policy |
| `order` | `order(refs)` | 视图重排（pin 块不可丢、可移位） | 仅 policy |
| `note` | `note.write/read/list` | scratchpad 工作笔记；普通块身份参与宇宙/视图；默认策略**永不丢 note 块**（安全默认） | agent 工具 `ctx_note`；policy 只读+保守压缩 |
| `view_state` | `view_state() → 上一轮视图摘要` | agent 的知情权（policy 保了什么丢了什么）；也是调试面 | agent 工具 `ctx_view`；policy 自知 |

**前置段固定行为（非原语，参数走 design 键，`cm_view` 引用其名）**：
`budget_checkpoint`（每轮）、`dedup`（tool-use prompt 去重，键控）、
`banner`（首轮对账单+触发式警告）、`boundary_marker`（task 题界插入）。
它们是框架行为，**不可被 policy/agent 调用**——审计词汇里保留其名仅为了
`cm_view` 能引用谁动了视图。

**会话内工具初始集**（opt-in 组件，`gan/components/<role>/cm/`；
`name == 文件 stem == tool_info()["name"]` 契约照旧；薄包装调用冻结核心，
后置段在咽喉点强制不变量——包装层不可信也不需要可信，对齐"AST 检查是
纵深防御"的哲学）：

| 工具 | 包装原语 | description 要点 |
|---|---|---|
| `ctx_index` | index | 枚举本会话可用上下文块（轨迹段/知识笔记/历史/笔记），只给元数据 |
| `ctx_fetch` | fetch | 按索引取一块内容进对话（全文/首尾/区间）；每次调用消耗工具调用预算 |
| `ctx_budget` | budget_query | 已用/剩余预算（tokens 分列 reasoning、调用数、时长） |
| `ctx_pin` | pin/unpin | 申请保留某块不被后续装配丢弃（框架保证尊重） |
| `ctx_note` | note | 跨轮工作笔记（写/读/列）；默认策略不丢笔记 |
| `ctx_view` | view_state | 查看上一轮实际发送的视图与被丢清单 |

seeds 初始选择：p/e 六件全选；task 选 `ctx_budget`/`ctx_note`
（task 的轨迹拉取走 `read_trajectory` slice——它是 index/fetch 在轨迹上的
特化前端，同一冻结核心，无第二套机制）。

**初始策略档位与键**（全部保留键：框架预声明、消费点钳制）：

- `cm_mode`：`passthrough`（默认，恒等视图）｜ `slice`（最近 K 轮全文，
  更早轮→占位；本轮 fetch 的详情保全文，更早 fetch 的→head_tail）｜
  `compact_conservative`（+ 超过 X 字符且早于 W 轮的 tool_output→excerpt）｜
  `custom`（组件）。
- `cm_window_k`（默认 pin 窗）、`cm_drop_floor_chars`（小块不丢——占位
  比内容还贵）、`cm_max_ops_per_turn`、`cm_policy_exec_ms`、
  `cm_note_cap_chars`。

**事件与记账**：

- 每轮 `cm_view`：ops（名+refs+结果）、视图统计（保留/丢弃/压缩块数、
  前后字符数）、dedup/banner 状态。
- op 级：`cm_violation`（拒绝+记录；连续违规→`cm_policy_disabled`，
  wedge breaker 同款）；`cm_policy_failed`（异常→fail-open passthrough）。
- 会话级：CM 摘要并入 per-session 成本记录（ops 数、估算节省字符数）。
- **记账口径**：账本只记**实付**（proxy 审计）；压缩只影响**未来轮**的
  输入，已花的 token 照实入账——"估算节省"是 L1 的派生指标，不与实付
  混同。

**刻意不做**：LLM 摘要型压缩（compact 无 LLM——语义摘要是 agent 自己的
活：`ctx_note` 写要点，原文可弃）；agent 侧 `drop`（其调用输出本身会进
历史，驱逐只能在视图层）；跨会话记忆（知识库承担）。

#### 5.2.4 文件归属：共享与角色池的划分（CM 落位）

**现状调查（`gan/framework/frozen.py` 是唯一权威）**：`gan/tools` 里
**"共享且可编辑"的类别今天不存在**——共享内容全部冻结，可编辑内容全部
角色自有：

| 路径 | 可写性 | 写者 |
|---|---|---|
| `gan/tools/work/common/**`、`design/**`、`deep/**`、`assembly.py` | ❌ 冻结 | 无人（不在任何角色 roots；preflight 对冻结管线破损 fail-fast） |
| `gan/tools/work/planner/**` | ✅ | planner（仅 `self_improve` seat） |
| `gan/tools/work/evaluator/**` | ✅ | evaluator（仅 `self_improve` seat） |
| `gan/components/task/**` + `registries/task.json` | ✅ | planner（`plan` seat；task 自己无源码权限） |
| `gan/components/planner\|evaluator/**` + 各自 registry/seed/schema_ext | ✅ | 各角色（仅 `self_improve` seat） |

"可用"与"可写"是两个正交分配：**可用**由 assembly 按角色组装
（`always_on_dirs` 把 work/common 装进每个编辑型角色的 toolset；components
按 design 选择），**可写**由 `SEAT_WRITE` 按 seat 收窄且各角色写面
seat-disjoint（p/e 并行 self-improve 的前提）。

**共享可编辑池为何不能有（碰撞机制）**：

1. **并行写面相交**：若共享文件在 p/e 双方 roots 内，两个 patch builder
   各自从**自己的 workspace**（`workspaces/<role>/outer_*/src`）抓取它 →
   两个 patch 都含同一 repo 路径；apply 串行但后者基于过期 base
   （workspace 不同步对方的 self-patch）→ **静默 last-writer-wins 回滚**。
   `SEAT_WRITE` 的 seat-disjoint 正是为排除这一点而设。
2. **归因污染**：patch 提交是 attribution-clean（只 stage 自己的文件）；
   共享文件的 commit 归属不明 → `component_drift`、receipt per-patch 事实、
   preflight 的 owner 分类（agent-fixable vs framework-failed）全部失真。
3. **registry/assembly 绑定被打破**：registry entry 只能引用本角色树、
   单写者 registry、assembly basename 冲突检测、`list_components` 的
   origin/pending 语义都以"一树一角色"为前提。
4. **heal/回滚作用域**：design heal 与 patch 回滚按角色走；共享文件回滚
   波及他人运行中的会话。
5. **需求不对称**：p（规划上下文）/ e（证据拉取）/ t（长会话压缩）对 CM
   的策略需求本就不同，共享源码把三者耦死。

**CM 的落位（三类池，不做共享可编辑）**：

- **池 A 冻结共享（nobody-writes）**：`gan/framework/cm/` 核心+契约+不变量
  （被 `TRUST_ANCHOR: gan/framework/*` 自动覆盖）+ 现有 work/common。
  跨角色必须一致的东西全部住这里：块模型、原语行为、占位模板、不变量。
  进化 = 框架发布（人改），preflight fail-fast。
- **池 B 角色自有可编辑（完全分开 ×3）**：`gan/components/<role>/cm/` 薄
  包装（+ `gan/tools/work/<role>/` + 各自 registry）。写者映射沿用现有
  seat：task 池 ← planner（`plan`）；planner 池 ← planner（`self_improve`）；
  evaluator 池 ← evaluator（`self_improve`）。**包装必须薄**（参数适配/
  标签），跨角色一致性由池 A 保证——包装层分歧是特性（各自进化），不是
  缺陷。
- **池 C 只读数据共享**：知识库。跨角色传播"怎么用 CM"的经验走数据
  （p 写 task 侧笔记、roles 经 access 通道读），不走共享代码。
- **不设晋升机制（已决策）**：池间边界静态——池 A 只随框架发布演进，
  池 B 不上移；跨角色一致性只能通过框架发布获得。

回答设计问题本身：**可用不分开**（共享冻结核心 + 按角色组装是对的，
完全分开可用池会无谓复制冻结语义），**可编辑必须完全分开**（每角色一棵
树、一个单写者 registry、seat-disjoint 写面）。CM 不新增任何例外——它
只是把现有三类格局补全了一层框架侧核心。

### 5.3 行为软约束

- 对账单尾部带一句预算状态提示（超支要求说明或压缩）——纯文本，零新机制。
- evaluator 的成本类检查点是其**进化空间**（它本来就能增删 eval-points /
  组件）：e 可以自主决定是否把"成本异常"立为 issue；p 必须以结构化 stance
  回应（含 `out_of_scope` / `deferred` 表达"该成本我控制不了"）。
  均衡责任由此分布在两个角色上，而不是框架单方面塞指标。

## 6. 失效模式与防规避

| 风险 | 对策 |
|---|---|
| 成本数字变成新的说服/操纵通道 | 只走对账单与结构化投影；不进 diff_summary/issue 自由文本（原则 2） |
| 砍上下文省钱 → 成绩崩 | 消费点钳制给下限；score 下降经既有 stagnation/选择回压；对账单永远伴随 score（原则 5） |
| 省掉必需动作（e 不做 eval-point） | 必需动作最小预算按 seat 拆分（evaluate 盲/揭示两相已有先例），预算键继承该拆分 |
| 谎报成本 / 伪造余量 | 账本只由框架写；meter 只读；聚合器是唯一比值来源（原则 1） |
| 上下文策略走私未脱敏内容 | 策略在脱敏之后、复用 AccessContext 与 redact；组件输出仍过 C2 上限；策略只能缩小可见集 |
| 预算耗尽伪装成功 / 丢评分 | 超限按现有 invalid/budget 语义留痕；None≠0 口径贯穿（原则 4） |
| 选择压力被噪声主导 | 归一化策略（per-question + 滑窗分布，§2.5）+ 观察期后才激活 cost_penalty（原则 7） |
| p 把 t 的预算键设满 → 成本爆炸 | 键值区间由框架给定并 clamp；p 自己的对账单会显示其决策的成本后果（责任内化） |

- **延后**（与 cost_tem 一致）：成本进 p/e 调度（无选择器挂点，等调度演进）；
  多模型定价归一（当前单模型，先记账不做）；memRL 式记忆加权（等数据量）。

### 10.0 相对 §5.1/§7 的勘误与既定决策

1. **`trajectory_read_mode`（default/slice）不随 C 落地**。§5.1 把它列进 task
   键族，但其消费端（轨迹索引预构建 + `read_trajectory` 的 slice 消费端）属
   §7 D；C 里声明它是死键（可设、零效果、静默无声），违背 C 判据"键生效事件
   入账本"。键随 D 与其消费端一起进 schema。
2. **`reasoning_effort` 设计键允许覆盖** models.yaml/broker 固定值，消费点 =
   **harness**（`domains/harness.py`）。依据：broker 模式下
   `run_harness_and_report` 有意忽略调用方 effort（注册时自 models.yaml 固定），
   消费点放 task_runner 会让设计键在 broker 模式静默失效；而 local/broker 两种
   模式下 harness 都能读 `GAN_TASK_DESIGN`。规则：枚举 `REASONING_EFFORTS`
   （low|high|max）内取值，缺省回落 models.yaml 值；parent 端
   `cost_keys_applied` 事件 + proxy 审计 per-call effort 双留痕（可离线核对
   "声明的 ≠ 实际用的"）。models.yaml 对 **model 本身**的独占裁决不变。
3. **`cost.token_budget_per_gen` 的 C 消费** = task `per_question_token_budget`
   的**上限 ceiling**（一题超过整代预算无意义）+ 对账单参考线（B1 已有）。
   整代预算执行不在 C：题间 ThreadPool 并行、harness 无法中途截断，归 E 的
   目标层。
4. **保留键物理形态 = 顶层 `cost` dict 固定槽**（三角色同形）：进
   `ROLE_SCHEMAS` 后自动进 `_RESERVED`（`add_config_key` 无法 shadow/抢占）；
   权威声明表在**冻结模块** `gan/framework/cost_keys.py`。刻意不进
   `schema_ext/<role>.json`（agent 可写面，保留键权威必须冻结）也不进
   `params`（自由无校验字典）。
5. **顺路修正**：(a) `receipt._design_diff.dynamic_keys_added` 需排除 `cost`，
   否则首次引入 cost 槽被误报为"新增 dynamic key"；(b)
   `scripts/local/regress_dynamic_keys.py` S1 断言 `allowed_keys("task")` 精确
   等于 `{prompt, tools, params}`，需同步加 `cost`。
6. **语义口径**：token 预算按"每次 chat run"执行（plan 的 patch 重试是同一
   轨迹上的续跑、计数重置），会话真实总量由账本照实记录（None≠0 不变）——
   软约束优先（原则 4），重试链可超 k×预算、可离线对出。B21 转发由
   `task_agent.py`（工件）完成：转发缺失属 Phase B 同款信任姿态，parent 事件
   + 轨迹 usage 可离线对出。design.json 未 bind 进 bwrap 沙箱，task 子代不能
   自读，必须 harness 中转。

### 10.3 验收（全部离线）

1. `set_config(key="cost")` 合法值接受、越界值/未知子键当场拒绝（design 不动）；
   `add_config_key` 无法声明/影子 `cost`。
2. 含 cost 键的设计经 `heal_design_keys` / `repair_dangling_designs` **不被剥**
   （判据 2）；人为移除 schema 声明仍不剥（C3 冻结直查）。
3. 越界设计值 → `cost_keys_applied.clamped` 带 requested/effective；生效值与
   手算一致；默认设计（无 cost 键）下全链路行为与 A/B 一致（纯增量回归）。
4. B21 链路：伪 design.json → harness payload 字段正确；`chat_with_agent`
   越限产生总结 turn + `token_budget_stop` 轨迹行 + `return_info`；
   `task_agent` 转发不丢。
5. **预算锦标赛可见**（判据 3）：两份不同 cost 设计的 smoke →
   `cost_keys_applied` 生效值不同、对账单预算节随设计变化、
   receipt `cost_keys_changed` 记录代际变更。
6. effort 覆盖：payload effort = 设计键值；proxy 审计 `llm_call` 的 per-call
   effort 与之一致；缺省回落 models.yaml 值。
7. 工具回归套件（deep gate S1–S4 / batch-6 / batch-8）触碰
   `gan/tools/design/set_config.py` 前后各跑一次，全绿。

### 10.4 顺序与不做

**顺序**：C0→C1→C2→C3→C4→C12→C5→C6→C7→C8→C9→C10→C11→C13→C14
（C14 的 schema 断言随 C1 同步改，其余测试收尾跑全量）。

记录，C 只做 per-question 预算**执行**，记账口径不变）；`params` 槽承载保留键；
`set_param` 改动（params 无消费者，不构成绕过）。

### 11.2 验收（全部离线）

1. `cm_view` 装配事件可对账（§7 判据）：每轮事件含 ops（名+refs+规则）与
   前后视图统计，事件里只有引用/尺寸、无块正文（防泄漏断言）。
2. policy 崩溃/违规 → fail-open passthrough + `cm_policy_failed`/
   `cm_violation` 事件，会话存活并产出有效结果；连续违规 → `cm_policy_disabled`
   （wedge breaker 同款语义）。
3. slice 模式下 `read_trajectory` 先返回索引，`fetch` 按块物化详情；
   `passthrough` 档输出与 D 前逐字节一致（纯增量回归）。
4. 同一 design 键切换 `passthrough`/`compact_conservative` 离线 A/B
   （fake-LLM smoke）：压缩档视图字符数下降、score 相关断言无系统性回退、
   两次的 `cm_view`/`cost_keys_applied` 生效值随键变化。
5. 不变量强制：构造越权 policy（造新内容/丢 pinned 块/扩大可见集）→ 后置段
   拒绝该 op + `cm_violation`，视图仍合法。
6. task 快照链：无 `gan/` 的 run-dir 中 seam 正常装配；`cm_snapshot` 事件的
   sha 与快照一致；differential gate 拒绝对快照源路径的 agent 写。
7. cm 保留键：越界值 → clamp 记录；`add_config_key` 无法声明任何 `cm_*`；
   heal/repair 保 cost 槽（含 cm 子键）——C 判据 2 的回归不破。
8. 工具回归套件（deep gate / batch-6 / batch-8 / c-dispatch / dynamic-keys）
   全绿；`test_cost_keys.py`、`test_cost_ledger.py` 回归全绿。

### 11.3 顺序、风险与不做

**顺序**：D1→D0→D13→D2→D3→D9→D4→D8→D16→D15→D6→D7→D10→D11→D12→D14→D17
（权威表先行，核心包次之，守卫随快照机制落地，消费端收尾跑全量）。

**风险表**（评审留档）：
- **快照投递是 D 最大的新增机制责任**：`gan/framework/cm/**` + 按选 policy
  文件每代拷贝，differential gate 必须同步覆盖（D13），否则 frozen 语义只剩
  拷贝时机一层的约束；preflight 对快照内核心文件破损 fail-fast（池 A 语义）。
- **task 侧 policy 开放顺序提前**（相对 §5.2.2"p 之后"）：压缩丢线索的风险
  由 clamp 下限 + stagnation + 对账单伴随 score 承接，回退是一个浅通道改动。
- **双记审计的存储增长**：`cm_view` 逐轮事件带 refs/统计（无内容），随会话
  长度线性；不设采样（对账完整性优先），离线分析侧已有分页读取先例。
- **执行面扩大**（§5.2 M 风险 3）：policy 每轮自动执行 → AST 负清单 + wedge
  breaker + fail-open 三层兜底；包装层薄、咽喉点在后置段（包装不可信、
  也不需要可信）。

**明确不做**（本轮决策 + 既有延后）：E 目标函数全套（λ/归一化策略/
packet.numeric 激活——不规划不实施）；p/e 侧装配时 policy 压缩（首期后评估）；
轨迹逐行偏移索引；LLM 摘要型压缩；agent 侧 drop；跨会话记忆；meter 逐 turn
自动注入；成本进 p/e 调度；多模型定价归一；memRL 式记忆加权。

### 11.4 实施勘误（相对 §11.0–§11.3，以代码为准）

1. **seam 契约 = `assemble_turn(msgs, outgoing) → (history_to_send, msg_to_send)`**：
   litellm 客户端每轮**重建**消息列表（对象身份不跨轮），装配点收敛在
   `_counting_llm`（全部 6 处 LLM 调用过同一咽喉）。规范历史保持 RAW：
   seam 只返回浅拷贝用于发送，调用后按 `hist[n_viewed:]` 重建规范链并把用户轮
   还原为原文——双记的"原始面"由此落在内存历史 + 轨迹行两处。
2. **块重绑定靠内容指纹 + 视图标记**：重建后的历史条目按 sha1 指纹映射回既有块；
   已烘焙的视图构件（`[block bN ...` 标记）按 id 重绑而非再注册——渲染幂等，
   压缩一次、跨轮持续（视图形态粘性）。
3. **dedup 落为 `dedup` 视图形态**（规划归为"前置段固定行为"）：老于窗口的
   `turn_output` 去掉逐轮重发的 tool-use 头部、换一行带内标记；新窗口内保留全文。
   `boundary_marker` 在 v1 是结构性 no-op（task 每题独立会话，会话内不存在题界），
   词汇保留给多题长会话。
4. **`cm_view` 事件走 events.jsonl**（role 归属，与 `cost_keys_applied` 同流），
   不占会话轨迹；cost_sessions 的 `cm` 摘要由 loop 在结算时从**存活会话对象**
   直接注入（真源），`cost_ledger._cm_summary`（轨迹聚合）保留为离线对账面。
5. **violation 审计在 ViewHandle 上**（不只 seam 流内）：policy 面的任何失败
   （face 越权 / op 预算 / pin / 未知块）当场计数并 emit，`_count` 以 `_audited`
   标记去重——handle 在 seam 外直调也不会丢审计。
6. **receipt `budget.kind` 增 `"cm"` 的语义**：policy 降级（disabled/失败）作为
   一种预算状态事实入账（`budget.cm` 节带摘要），不改变 exhausted 语义；
   plan 与 self 两条 receipt 通路都接。
7. **preflight 增 `cm` 节（advisory）**：包装组件走常规 AST 能力检查，policy
   文件加冻结 no-LLM/no-network 门；**执法点在快照物化**（materialize 拒绝即
   fail-open passthrough），preflight 只让结果在启动前可见。快照源路径在
   `gan/framework/*` 信任锚内，agent 补丁结构性不可达（无需新差分门）。
8. **三角色键组完全同形**（§11.1 拟定表定稿）：`cm_mode/cm_window_k/
   cm_drop_floor_chars/cm_max_ops_per_turn/cm_policy_exec_ms/cm_note_cap_chars`
   三角色一致；task 侧消费点 = 快照 seam + `ctx_budget/ctx_note`。

### 11.5 整改勘误（2026-10-12，P0 修复轮；基线 f6e4248，逐项有测试）

> D 阶段结构落地但集成层有真缺陷。本节记录修复轮对 D/B 集成层的实际修复
> 与对 §11.4 的再勘误。默认设计（passthrough）下视图字节不变。

1. **"规范历史保持 RAW"此前并未成立（真 bug）**：`agent/llm.py` 的
   text→content 入口转换会**原地 pop** 它收到的字典的键；seam 的
   `_render`/passthrough 对未替换条目交回 canonical 的同一对象 → 每次 LLM
   调用后规范历史被剥成 `{"role": …}` 空壳，§11.4.1 的 rebuild 复用
   `raw_history` 恰把空壳留在规范链（模型自第 2 轮收到无内容历史）。

### 11.7 源码级主管理路径：P0/P1 原语化 + 基线组装外置（2026-10-13；基线 0de8643）
