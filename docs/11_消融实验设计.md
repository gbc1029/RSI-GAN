## 1. 目标与总览

RSI-GAN 是 GAN 式三角色自进化框架（`task_agent` + `planner` + `evaluator`）。
消融实验要回答四类问题：

| 组 | 问题 | 轴 |
|---|---|---|
| A | 三角色架构本身是否必要、角色自进化是否有收益 | 角色层 |
| B | 修改底层源码（deep）到底有没有价值 | 深浅层进化 |
| C | evaluator 反馈如何影响进化 | 反馈信号 |
| D | 父代历史轨迹是否必要 | 轨迹可见性 |
| E | 反馈信号（评估点）是否真正影响进化 | 评估点增减 |

**基线主臂 A0 = 完整系统**（`ablation.*` 全默认、`source_access.deny_deep=false`）。

**消融臂一次只开一个**；组合臂（如 A6+B 组）按 §5 矩阵显式声明。

## 2. 消融矩阵

### A 组｜角色层消融（验证 GAN 三角色框架）

| 臂 | 开关 | 语义 | 对比假设 |
|---|---|---|---|
| A0 | （全默认） | 完整系统 | 基线主臂 |
| A1 | `ablation.disable_planner=true` | 跳过 plan，task 用父代(seed)配置跑，evaluator 照常评分 | planner 是否必要（无 planner 则 task 永不改进） |
| A2 | `ablation.disable_evaluator=true` | 跳过 evaluate，planner 只拿 benchmark 分改进 | evaluator 反馈评估是否必要 |
| A3 | `ablation.disable_self_improve=true` | 双角色都不 self_improve（plan/evaluate 照常） | 角色自身进化能否提升性能 |
| A4 | `ablation.disable_planner_self_improve=true` | 仅冻结 planner 自进化 | planner 自进化的边际收益 |
| A5 | `ablation.disable_evaluator_self_improve=true` | 仅冻结 evaluator 自进化 | evaluator 自进化的边际收益 |
| A6 | `ablation.task_only_single_round=true` | 只跑 gen0 task 单轮（seed 配置），完全无进化 | **整个进化机制的总收益**（最底层基线） |

> 术语约定：「进化/自进化」= 角色 `self_improve`（改自己）；`plan`（planner 改
> task）与 `evaluate`（evaluator 评 task）**照常**，不受 A3/A4/A5 影响。

### B 组｜深浅层进化轴（修改深度 L2/L3）

| 臂 | 开关 | 语义 | deep(view) | deep(modify) | shallow(prompt) | shallow(组件选择) |
|---|---|---|---|---|---|---|
| A0 | （全默认） | 完整 | ✅ | ✅ | ✅ | ✅ |
| B1 | `source_access.deny_deep=true` | 仅浅层 | ❌ | ❌ | ✅ | ✅ |
| B2 | `ablation.deep_view_only=true` | 禁写源码、保留只读 | ✅ | ❌ | ✅ | ✅ |
| B3 | `ablation.shallow_prompt_only=true` | 只许改 prompt | ❌ | ❌ | ✅ | ❌ |
| B4 | `ablation.disable_shallow=true` | 禁浅层、只许改源码 | ✅ | ✅ | ❌ | ❌ |

> B 组四个臂构成完整 2×2：B1（禁 deep）/ B2（deep 只读）/ B3（只改 prompt）/
> B4（只改源码）。目标：**Agent 修改底层源码到底有没有价值**（B2 读源码 vs
> B4 改源码）与 **提示词进化 vs 组件选择进化**（B3）。

### C 组｜反馈信号轴

| 臂 | 开关 | 语义 |
|---|---|---|
| C1 | `ablation.disable_blind=true` | 关闭盲评：evaluator 一开始就看到 benchmark 分（跳过盲评纪律） |
| C2 | `ablation.feedback_numeric_only=true` | 无反馈：planner 只拿 benchmark 分数，无 issues/digest/diff |
| C3 | `ablation.feedback_no_diff_summary=true` | 去掉 diff 差异摘要（planner/evaluator 两侧） |
| C4 | `ablation.feedback_predicted_score_only=true` | 数值奖励替代文本反馈：planner 只拿 `predicted_score`（evaluator 盲评预测分） |

> C2 的数值 = **客观 benchmark 分**；C4 的数值 = **evaluator 主观
> `predicted_score`**。C4 是「自然语言反馈 vs 纯数字奖励」的对照，需要改
> evaluator 输出契约的消费侧（planner 输入投影），evaluator 照常产出。

### D 组｜轨迹可见性轴

| 臂 | 开关 | 语义 |
|---|---|---|
| A0 | `ablation.trajectory_visibility=parent` | 基线：planner=直接父代；evaluator=当前+父代；self_improve=本 outer+父代 |
| D1 | `ablation.trajectory_visibility=current` | 仅当前代（plan 阶段当前代无轨迹 → 空集） |
| D2 | `ablation.trajectory_visibility=all` | 全部历史代际 |

> 目标：**父代历史信息是否是进化有效的前提**。

### E 组｜评估点增减轴

| 臂 | 开关/操作 | 语义 |
|---|---|---|
| E1 | 移除 `trajectory_quality` | 去轨迹质量判据 |
| E2 | 移除 `hard_failure` | 去硬失败判据 |
| E3 | 移除 `reward_hacking` | 去奖励黑客检测 |
| E4 | 移除 `rule_violation` | 去作弊检测 |
| E5 | 移除全部 4 个 | 评估点整体贡献 |

> E1-E5 靠 opt-in 组件机制实现：`ablation.evaluator_drop_eval_points` 在
> **首次 seed**（evaluator design 文件缺失）时从 `tools` 槽移除指定
> eval_point；配合 `ablation.freeze_evaluator=true` 冻结 evaluator design，
> 防止 self_improve 把组件选回来。已有 design 文件是权威的，改名单需删
> design 文件或手动 `deselect_component`（见 §4 执行说明）。

## 4. 执行说明（run 命令）

```bash
# A0 完整系统（基线主臂）
python scripts/run_gan.py --domains paper_review --subset _filtered_100_train \
  --num_samples 2 --outer 2 --inner 3 --output_dir outputs/ablation/A0

# 单臂示例
python scripts/run_gan.py --domains paper_review --subset _filtered_100_train \
  --num_samples 2 --outer 2 --inner 3 \
  --ablation disable_planner=true --output_dir outputs/ablation/A1

# B1 走独立键
python scripts/run_gan.py --domains paper_review --subset _filtered_100_train \
  --num_samples 2 --outer 2 --inner 3 \
  --ablation deny_deep=true --output_dir outputs/ablation/B1   # 见 §3 注

# E 组：先删 evaluator design 文件（或新建 run 目录），再带 drop 名单 + 冻结
python scripts/run_gan.py --domains paper_review --subset _filtered_100_train \
  --num_samples 2 --outer 2 --inner 3 \
  --ablation evaluator_drop_eval_points=trajectory_quality,hard_failure \
  --ablation freeze_evaluator=true --output_dir outputs/ablation/E1E2
```

> `--ablation evaluator_drop_eval_points=a,b,c`：逗号分隔；值推断为列表。
> `--ablation deny_deep=true` 作为 B1 的 CLI 别名映射到
> `source_access.deny_deep`（见 §3 注，具体别名行为以实现为准）。

## 6. 指标与统计约定

- **strict**：harness 精确小写匹配（`report.json.total`，coverage<1 时排除无效样本——核对计数而非分母）。
- **lenient**：离线重解析 verdict（逐行 parse-method 审计）。
- **excess** = `max(0, (acc − rg)/(1 − rg))`，`rg` = random_guess_accuracy。
- **coverage** / **random_guess_accuracy**：harness 记录。
- 显著性：bootstrap CI（n≥2 样本才进 significance 文件；n=1 是噪声）。
- 每臂至少 **outer=2、inner=3、num_samples≥2**，多次 seed 取平均。

## 7. 外部 baseline

### 7.1 RQGM（Red Queen Gödel Machine，git submodule）

- 仓库：`baselines/rqgm`（`https://github.com/kingkillery/red-queen-godel-machine`，MIT）。
- 桥接：`baselines/rqgm_bridge/`（`convert.py` 数据转换 + `run.py` 调
  `run_rqgm("llm", ...)`，复用 RQGM 自带 `llm_providers` 不改子模块）。
- **已知局限**：RQGM 的 reviewer 只看 coder 的 artifact 文本、看不到论文，
  在 `paper_review` 上退化为格式检查；coder 角色完整有效（`prompt_input=论文`、
  `answer=outcome`）。回退 C 方案的触发条件：若 reviewer 退化导致结论不可用，
  fork RQGM 改 reviewer 评估逻辑（见 `baselines/rqgm_bridge/README.md`）。

### 7.2 原始 HyperAgents（DGM-H）flow

```bash
python -m domains.harness --domain paper_review --model openai/gpt-4o \
  --run_id baseline_dgmh --subset _filtered_100_train --num_samples 2
python -m domains.report --domain paper_review --dname ./outputs/baseline_dgmh
```

即「无进化的单轮 task agent」外部对照，与 A6 的差异是 A6 走 GAN 框架（同 seed
配置、同 harness 管道），DGM-H 走原始 harness 入口——两者交叉验证「进化总收益」。

### 7.3 baseline 记录字段

每个外部 baseline 记录：模型、seed、num_samples、strict/lenient acc、excess、
coverage、random_guess_accuracy、总 token/墙钟成本。与本仓库内部臂同表对比。
