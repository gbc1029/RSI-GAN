## 1. 目标与总览

RSI-GAN 是 GAN 式三角色自进化框架（`task_agent` + `planner` + `evaluator`）。
消融实验要回答四类问题：

| 组 | 问题 | 轴 |
|---|---|---|
| A | 三角色架构本身是否必要、角色自进化是否有收益 | 角色层 |
| B | 修改底层源码（deep）到底有没有价值 | 深浅层进化 |
| C | evaluator 反馈如何影响进化 | 反馈信号 |
| D | 父代历史轨迹是否必要 | 轨迹可见性 |
| E | 反馈信号（评估点）是否真正影响进化 | 评估点增减 |

**基线主臂 A0 = 完整系统**（`ablation.*` 全默认、`source_access.deny_deep=false`）。

**消融臂一次只开一个**；组合臂（如 A6+B 组）按 §5 矩阵显式声明。

## 2. 消融矩阵

### A 组｜角色层消融（验证 GAN 三角色框架）

| 臂 | 开关 | 语义 | 对比假设 |
|---|---|---|---|
| A0 | （全默认） | 完整系统 | 基线主臂 |
| A1 | `ablation.disable_planner=true` | 跳过 plan，task 用父代(seed)配置跑，evaluator 照常评分 | planner 是否必要（无 planner 则 task 永不改进） |
| A2 | `ablation.disable_evaluator=true` | 跳过 evaluate，planner 只拿 benchmark 分改进 | evaluator 反馈评估是否必要 |
| A3 | `ablation.disable_self_improve=true` | 双角色都不 self_improve（plan/evaluate 照常） | 角色自身进化能否提升性能 |
| A4 | `ablation.disable_planner_self_improve=true` | 仅冻结 planner 自进化 | planner 自进化的边际收益 |
| A5 | `ablation.disable_evaluator_self_improve=true` | 仅冻结 evaluator 自进化 | evaluator 自进化的边际收益 |
| A6 | `ablation.task_only_single_round=true` | seed 配置的任务单轮，完全无进化；按 §6.2 每个 outer 重复一轮，覆盖全部 genid 题集 | **整个进化机制的总收益**（最底层基线，匹配对照） |

> 术语约定：「进化/自进化」= 角色 `self_improve`（改自己）；`plan`（planner 改
> task）与 `evaluate`（evaluator 评 task）**照常**，不受 A3/A4/A5 影响。

### B 组｜深浅层进化轴（修改深度 L2/L3）

| 臂 | 开关 | 语义 | deep(view) | deep(modify) | shallow(prompt) | shallow(组件选择) |
|---|---|---|---|---|---|---|
| A0 | （全默认） | 完整 | ✅ | ✅ | ✅ | ✅ |
| B1 | `source_access.deny_deep=true` | 仅浅层 | ❌ | ❌ | ✅ | ✅ |
| B2 | `ablation.deep_view_only=true` | 禁写源码、保留只读 | ✅ | ❌ | ✅ | ✅ |
| B3 | `ablation.shallow_prompt_only=true` | 只许改 prompt | ❌ | ❌ | ✅ | ❌ |
| B4 | `ablation.disable_shallow=true` | 禁浅层、只许改源码 | ✅ | ✅ | ❌ | ❌ |

> B 组四个臂构成完整 2×2：B1（禁 deep）/ B2（deep 只读）/ B3（只改 prompt）/
> B4（只改源码）。目标：**Agent 修改底层源码到底有没有价值**（B2 读源码 vs
> B4 改源码）与 **提示词进化 vs 组件选择进化**（B3）。

### C 组｜反馈信号轴

目标：evaluator 反馈**形式**如何影响进化。

| 臂 | 开关 | 语义 |
|---|---|---|
| C1 | `ablation.disable_blind=true` | 关闭盲评：evaluator 一开始就看到 benchmark 分（跳过盲评纪律）——检验盲评机制能否防止过拟合 benchmark |
| C2 | `ablation.feedback_numeric_only=true` | 无文本反馈：planner 拿两个分数（`predicted_score` + `benchmark_score`），去掉 issues/digest/diff |
| C3 | `ablation.feedback_no_diff_summary=true` | 去掉 diff 差异摘要（planner/evaluator 两侧）——检验代码变更 diff 信息对 planner 改进有无帮助 |
| C4 | `ablation.feedback_benchmark_score_only=true` | 仅给 benchmark 分数：planner 只拿 `benchmark_score`（无预测分、无文本反馈）——检验客观分的作用 |

> C2 = 两分数（`predicted_score` + `benchmark_score`）无文本；C4 = 单分数（仅
> `benchmark_score`）无预测分无文本。C2 是「文本反馈 vs 数值反馈」的对照，C4 检验
> 「预测分是否有增量价值」——两者都在 evaluator 输出契约的消费侧（planner 输入投影）
> 裁剪，evaluator 照常产出。

### D 组｜轨迹可见性轴

| 臂 | 开关 | 语义 |
|---|---|---|
| A0 | `ablation.trajectory_visibility=parent` | 基线：planner=直接父代；evaluator=当前+父代；self_improve=本 outer+父代 |
| D1 | `ablation.trajectory_visibility=current` | 仅当前代（plan 阶段当前代无轨迹 → 空集） |
| D2 | `ablation.trajectory_visibility=all` | 全部历史代际 |

> 目标：**父代历史信息是否是进化有效的前提**。

### E 组｜评估点增减轴

| 臂 | 开关/操作 | 语义 |
|---|---|---|
| E1 | 移除 `trajectory_quality` | 去轨迹质量判据 |
| E2 | 移除 `hard_failure` | 去硬失败判据 |
| E3 | 移除 `reward_hacking` | 去奖励黑客检测 |
| E4 | 移除 `rule_violation` | 去作弊检测 |
| E5 | 移除全部 4 个 | 评估点整体贡献 |

> E1-E5 靠 opt-in 组件机制实现：`ablation.evaluator_drop_eval_points` 在
> **首次 seed**（evaluator design 文件缺失）时从 `tools` 槽移除指定
> eval_point；配合 `ablation.freeze_evaluator=true` 冻结 evaluator design，
> 防止 self_improve 把组件选回来。已有 design 文件是权威的，改名单需删
> design 文件或手动 `deselect_component`（见 §4 执行说明）。

### 3.0 非消融的设计写入闸门（R2，2026-10-26）

与 B3/B4 同一个执行层，但**不是消融臂**，因此不在 `ablation.*` 下、也不进消融矩阵。

| 配置键 | 消费者链 | 行为 |
|---|---|---|
| `design.prompt_rewrite_min_similarity`（默认 `0.5`） | `build.py` → `AccessBroker(prompt_rewrite_min_similarity=)` → `role_process.broker_info` → `_RemoteBroker` → `context.design_limits()` → `set_prompt.prompt_rewrite_error`（`set_prompt` 与 `set_config(key="prompt")` 共用） | 与旧文本的**字符级**相似度低于阈值 ⇒ 判定为整段重写并**拒绝**（设计不动、也不留 record）；`0` = 关闭 |

- 动机：`set_prompt` 原先只有 shape 校验（非空 + ≤20000 字符），于是 planner 最省力的
  "改进"就是整段替换 task prompt。Stage-A 实测 385 → 998 → 1351 字符
  （行级 similarity 0.24 / 0.18），task agent 从"一个词"变成"写完整评审"；把标签从
  评审里捞回来之后该臂仍然垫底 ⇒ 改坏的不只是格式，还有判定本身。**A0（全通道开）是
  唯一能让 planner 自进化与 evaluator 自进化同时存在的臂，也是分数最低的臂。**
- 为什么用字符级而不是行级：`prompt_change_facts.similarity` 是**行级** `SequenceMatcher`，
  对单行 prompt 的任何编辑都算 `0.0`（1 行 vs 1 行全不同），分不清改错字和整段替换。
  为此新增 `char_similarity` 事实键（同时进 `PROMPT_FACT_KEYS`，仍是纯数字，不含文本）。
- 始终放行：空 prompt 的首次写入、与旧文本完全相同、**写入 generation-0 seed**
  （回退漂移是合法恢复路径，堵住它会让坏 prompt 无路可回）。
- 跨进程注意：新键必须在 `role_process.broker_info` 里镜像到 `_RemoteBroker`，否则
  子进程的设计工具读到默认 `0.0`，闸门静默失效（与 B 组开关同一失效模式）。
- 回归：`scripts/local/test_prompt_gate.py`（27 条断言，含镜像检查）。

### 3.0b 内层停滞判据（R4，2026-10-26）

`stagnation_patience` 原来拿 `benchmark.mean` 的 parent-child 差判"有没有进展"——但主线每代
`derive_sample_seed(base_seed, genid)` 重抽题集，30 题的标准误约 **0.16**，与要追的效应同量级，
所以"停滞"判定基本是在读噪声。

| 判据 | 来源 | 成本 | 分辨率 |
|---|---|---|---|
| **anchor_correct（现默认）** | `runs/<genid>/report.json` 中**锚点题**的答对数（`ckpt/sample_seed.json: anchor_ids`） | **0**（主线本来已答） | `sampling.anchor_k` 步长：k=10 ⇒ 0..10，粗但**跨代无噪声** |
| `benchmark_mean`（回落） | `benchmark.mean` | 0 | 细但**跨代不可比** |

- 规则：只有候选与父代都能算出锚点答对数时才用锚点口径；否则回落分数口径（无锚点、非
  parent-scored 域、父代无 report）。**`sampling.anchor_k: 0` 即可退回旧行为**，无需新开关。
- 锚点题若该代没作答，**记为错**（同一分母，可比），不是"无数据"。
- `inner_done` / `stagnation_break` 事件新增 `improved_metric` / `anchor_correct` /
  `anchor_parent_correct`，regime 可审计。
- 回归：`scripts/local/test_stagnation_anchor.py`（15 条断言，含"只换题不换锚点不算改进"
  与"锚点真涨但总分降仍算改进"两个方向检查）。


### 3.1 新沙箱下的执行位置（2026-10-15）

fix3 沙箱合并后，planner/evaluator 会话在 `role_process` 子进程内运行（deep/shallow
工具经 `_RemoteBroker` RPC 触达 outer_worker 里的真 `AccessBroker`）。开关按
「在哪一侧生效」分三类：

| 类别 | 开关 | 执行位置 | 跨进程要求 |
|---|---|---|---|
| 编排层投影 | A1–A6、C1–C4、D、E | `loop.py`（outer_worker 进程）在调用角色前算出参数/投影 | 参数随 IPC 明文下发，无需特殊处理 |
| broker 深度门 | B1、B2、B3(deep 半边) | `build.py` 构造的 `AccessBroker`（outer_worker 进程），子进程经 RPC 触达 | `grant()` 抛的 `SourceAccessDisabled` 必须经 IPC **原样重建**（`role_process.py` 异常表），否则 deep 工具的 `except SourceAccessDisabled` 捕不到 |
| 子进程浅层门 | B3(浅层半边)、B4 | 设计工具 `shallow_op_error` 在**子进程**内判定，读 `actx.broker` 的 B 组标志 | 标志经 `broker_info`（`_RemoteBroker` 属性）下传；缺则子进程恒 all-false、B3/B4 静默失效 |

另：三个角色方法结果（`plan`/`evaluate`/`self_improve`）跨进程时受
`role_process._validated_result` 的**精确字段契约**约束，该契约必须与角色返回字典同步
（`301dc48`：补 `token_budget_exhausted` 与 `EvalContext.truncated`；不补则 plan 表现为
`inner_invalid(reason=planner_failed)` 且得分为 null）。回归：
`scripts/local/verify_deny_deep.py`（进程内 19 项）+
`scripts/local/test_b1_cross_process.py`（跨进程 14 项，走真实 IPC 往返）。

## 4. 执行说明（run 命令）

> **【2026-10-15 新沙箱对齐】入口只有 driver 模式**：`--in-process` 已硬禁用（它绕过
> 沙箱）；必须以普通用户经 `sudo` 启动并显式给出三个沙箱账户，`--repo_root` 指向仓库，
> `--output_dir` 落在**原生 Linux 文件系统**（需 POSIX ACL）——禁用 `/mnt/c` DrvFS、
> 仓库内/其父目录、`/tmp`、home 及其父目录；已存在的 output_dir 不得含源码/凭证标记。
> 前置条件见 §8 与 README「Environment deployment」。

```bash
REPO=/path/to/RSI-GAN                      # 仓库根
OUT=/opt/rsi-gan/runs/ablation             # 每臂一个子目录；原生 fs，归 sudo 调用者
ARM=A0                                     # 本臂名
ABL=()                                     # 本臂开关（见下方各臂示例）

sudo -E env \
  GAN_TASK_SANDBOX_USER=rsi_gan_task \
  GAN_PLANNER_SANDBOX_USER=rsi_gan_planner \
  GAN_EVALUATOR_SANDBOX_USER=rsi_gan_evaluator \
  "$REPO/venv_nat/bin/python" scripts/run_gan.py \
  --repo_root "$REPO" \
  --domains paper_review --subset _filtered_100_train \
  --num_samples 2 --outer 2 --inner 3 \
  --skip-analysis \
  "${ABL[@]}" --output_dir "$OUT/$ARM"

# 各臂只改 ABL：
#   A1 : ABL=(--ablation disable_planner=true)
#   A6 : ABL=(--ablation task_only_single_round=true)
#   B1 : ABL=(--ablation deny_deep=true)                        # 别名 → source_access.deny_deep
#   B4 : ABL=(--ablation disable_shallow=true)
#   C4 : ABL=(--ablation feedback_benchmark_score_only=true)
#   D2 : ABL=(--ablation trajectory_visibility=all)
#   E1E2: ABL=(--ablation evaluator_drop_eval_points=trajectory_quality,hard_failure \
#              --ablation freeze_evaluator=true)
```

> `--ablation evaluator_drop_eval_points=a,b,c`：逗号分隔；值推断为列表。
> `--ablation deny_deep=true` 作为 B1 的 CLI 别名映射到
> `source_access.deny_deep`（`scripts/run_gan.py` 已实现：`key == "deny_deep"` 走
> `overrides["source_access"]`，其余落 `ablation.*`）。
> E 组：先删 evaluator design 文件（或新建 run 目录），再带 drop 名单 + 冻结。

- 里程碑 B 的非 `ablation.*` 键（`outer_select.*` / `fitness.*` / `mome.*` /
  `eval.*`）走 `--set SECTION.KEY=VALUE`（`run_gan.py`，可重复、点路径、
  支持 JSON 列表），不要手改 `loop.yaml`。
- 每臂独立 `output_dir`；`SKIP_DONE=1` 依据 `events.jsonl` 的 `driver_done`
  跳过已完成臂。**E 组**的 drop 名单只在首次 seed 生效，重跑必须先删目录。
- 每臂 stdout 落 `$BASE_OUT/_logs/<arm>__<rep>.log`，机器可读汇总在
  `$BASE_OUT/_matrix_summary.txt`（`arm / output_dir / rc / 时长`）。

## 6. 指标与统计约定

- **strict**：harness 精确小写匹配（`report.json.total`，coverage<1 时排除无效样本——核对计数而非分母）。
- **lenient**：离线重解析 verdict（逐行 parse-method 审计）。
- **excess** = `max(0, (acc − rg)/(1 − rg))`，`rg` = random_guess_accuracy。
- **coverage** / **random_guess_accuracy**：harness 记录。
- 显著性：配对 bootstrap CI + 精确 McNemar；配对单元 = `(rep, question)`
  （`N_REPEATS>1` 时 CI 含 run-to-run 方差）。
- 每臂至少 **outer=2、inner=3、num_samples≥2**；跨臂比较建议
  `num_samples≥30`、`N_REPEATS=3`、`sampling.base_seed` 固定。
- **固定 seed 而非多 seed 平均**：题目由 `derive_sample_seed(base_seed, genid)`
  派生，固定 `base_seed` 才能让**同 genid 的不同臂抽到同一批题**（配对前提）；
  run-to-run 方差改由 `N_REPEATS` 估计。二者不可兼得，本实验选「固定 seed + 重复 run」。
- **多重比较**：主族 = **A1–A5 vs A0**（等预算的组件消融），用 **Holm-Bonferroni**
  校正（collector 自动输出 `p_holm` / `sig` 列，FWER=0.05）；**A6 不进本族**（见
  §6.2，单独一节报告）。B/C/D/E 组内与跨组比较属探索性，只报效应量与 CI。

### 6.1 等算力约定：`loop.stagnation_patience` 必须 ≥ `INNER`

**规则**：跑跨臂消融矩阵时，必须显式设
`--set loop.stagnation_patience=<INNER>`（`INNER=3` 时即 `3`），或更大的值。

**理由**：`gan/framework/loop.py` 的内层循环在 `no_improve >= patience` 时
`stagnation_break` 提前退出，而 `no_improve` 在**每个 outer 开头重置**。默认
`patience=2`、`INNER=3` 时，某臂可能在第 2 个内层代就提前停止，导致：

1. **等算力被破坏** —— 该臂的「最终代」不是在同等预算下取得的，组件效果与
   进化预算混淆，横向比较不再干净；
2. **genid 错位** —— 题目按 `derive_sample_seed(base_seed, genid)` 派生，
   **genid 不同题目就不同**；最后一层 genid 不一致时配对检验的交集退化为锚核。

设 `patience >= INNER` 后，早停条件在最后一个内层代之前不可能满足（等价于
「跑满预算」），保证每臂得到**完全相同的 genid 集合** `0 … OUTER×INNER-1`。

**记录方式**：该键属于**实验约定**而非消融开关，随 `--set` 传入；实际值可在
`events.jsonl` 的 `driver_start.cfg_overrides` 中审计，臂目录名不构成证据。

### 6.2 A6 匹配对照设计（matched baseline）

**机制事实**：A6（`ablation.task_only_single_round=true`）走
`loop._run_task_only_single_round()`，**每个 outer worker 只做一轮**就返回；
而 genid 由 `_gen_counter = _max_int_genid() + 1` 初始化（树是追加式 JSONL，
跨 worker 持久），因此 **`--outer N` 会让 A6 依次产出 genid `0 … N-1`**，
每一轮的题集 `derive_sample_seed(base_seed, genid)` 正好等于演化臂同一 genid
所用的题集。产物落在 `runs/<genid>/report.json`（与普通代一致）。

**设计要求**：A6 必须跑成「同一 artifact × 全部题集的重复评测」，而不是只跑
genid 0 的单点。artifact 恒定，因为每轮都复用 `tree.get("initial")` +
`_empty_plan_result(_initial_task_config())` + `_pin_outer_base(1)`。

| 项 | 要求 |
|---|---|
| `OUTER` | **必须等于演化臂的总代数**（`OUTER×INNER`）。主臂 2×3=6 → A6 用 `--outer 6` |
| `INNER` | 对 A6 无影响（在外层循环之前返回），填 `1` 即可 |
| `sampling.mode` | **必须 `seeded`**。`legacy_prefix` 会让每轮同一批题，失去匹配意义 |
| `sampling.base_seed` | 与演化臂**必须相同**，否则题集对不上 |
| `loop.stagnation_patience` | 主臂侧必须 ≥ `INNER`（见 §6.1），否则演化臂代数不足、genid 错位 |
| `output_dir` | **单独 `BASE_OUT`**（如 `.../abl_a6_matched_<stamp>`），不与主矩阵混放 |
| 报告 | **单独一节**，不并入 A1–A5 的配对表与 Holm 族 |

**得到的三类比较**：

1. **A6 vs A0 最终代**：两者 `acc_final` 都取自 genid `G-1` → 同一套题，配对
   单元 `num_samples × N_REPEATS`（如 30×3=90）。这是「进化机制总增益」的正式数字。
2. **逐代配对**：A0 的 gen `g` vs A6 的 gen `g`（同题），可画配对趋势。
3. **匹配对照曲线**：A6 各代应基本持平（同一 artifact，只受题目难度与 LLM
   随机性影响）；`A0(g) − A6(g)` 即剔除题目难度波动后的真实增量。

**结果目录**：A6 的 `runs/` 下应有 `0 … G-1` 共 `G` 个 genid 目录（不是重复的
`0`）；逐代 `question_ids_passed ∪ question_ids_failed` 必须与 A0 同 genid 完全一致
——这是该设计的**验收条件**，跑完先验一次再进统计。

**统计声明（必须随报告写出）**：

> A6 是匹配对照基线：同一个未演化 artifact 在 A0 用过的每一套题上各评测一次
> （genid `0 … G-1`），因此 A6 与 A0 第 `g` 代在同一题集上配对。A6 的多条记录是
> 同一 artifact 的重复评测，其 `score_mean` / `score_best` 不代表演化进展，只有
> `acc_final`（genid `G-1`）用于与 A0 最终代配对比较。

**已知边界**：A6 的预算（1 代）× 演化臂（`G` 代）不同，因此 A6 vs A0 的差异
**同时包含「机制」与「预算」**。它回答的是「整套机制值不值」，不是「某个组件值
不值」——后者由 A1–A5 在**等预算**下回答。两类结论不可互相替代。

**回退方案**：若预算紧张、只需要「A6 vs A0 最终代」一个数字，可改用
`--set sampling.mode=legacy_prefix`（所有代固定前 `num_samples` 行）使两臂同题；
代价是失去题目面与逐代对照。
