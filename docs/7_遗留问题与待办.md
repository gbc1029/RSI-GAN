## 1. 沙箱隔离

> 主体位于 `domains/harness.py`（bwrap 沙箱路径）与调用方 `gan/framework/task_execution.py`。
> **背景**：v5/fix1 已落地"基准标签仅经 CLI `--dataset_root` 传给父 harness"（子进程 env 剔除 `GAN_DATASET_ROOT`）。本节是**该改造之后**仍存在的问题。

### 1.1 未披露缺陷

#### S1 — `--unshare-all` 后跟 `--share-net`，网络实际未隔离 `新发现` `中`

- **现象**：`domains/harness.py:78-79` 连续出现 `"--unshare-all",` 与 `"--share-net",`。bwrap 选项按出现顺序生效，`--share-net` 的语义是"**不** unshare 网络命名空间"，故它把 `--unshare-all` 隐含的网络 unshare 重新关掉 → 沙箱与宿主共享网络。
- **触发**：任何沙箱路径运行（task agent 具 `bash`/`editor` 技能时可直接外连）。
- **旁证**：`docs/6` §6.4 记录了 `httpx.get → 200`（网络本身连通）；§5.1 实测表亦记 `--unshare-net` **可用**——即能力具备但未接线。
- **修法**：删除 `--share-net`（保留 `--unshare-all`），或显式写 `--unshare-net`。

#### S2 — 每题子进程无 `timeout=` `新发现` `中`

- **现象**：`domains/harness.py:159-166` 的 `subprocess.run(...)` **未传** `timeout=`；对比 `gan/framework/task_execution.py:148` 的外层 `timeout=timeout`。
- **后果**：单题挂死阻塞整个 `ThreadPoolExecutor`（`:298-317` 退出时等全部 future），整代仅在外层 1800s 被杀；而 `predictions.csv` 仅在 `save_interval` 边界（`:334-337`）或最终（`:341`）落盘 → **一次挂死可丢掉整代已有结果**。
- **触发形态**：子进程无响应——`docs/6` §6.4 记录的"缺 `OPENAI_API_BASE` 时长挂"即此形态。
- **修法**：给 `subprocess.run` 加 per-question timeout，并把失败记录与 predictions 一并纳入 `save_interval` 落盘。

#### S3 — 结果 sentinel 可被 task agent 伪造 `新发现` `中`

- **现象**：结果由父进程从子进程 stdout **反向匹配前缀行**解析（`domains/harness.py:170-173`），前缀 `__RSI_TASK_RESULT__` 是仓库内公开常量（`harness.py:19`、`domains/task_worker.py:11`）。
- **后果**：task agent 或其工具只要打印一行 `__RSI_TASK_RESULT__{...}` 即可**劫持判定结果**——把"子进程 stdout"当可信通道是信任边界的位置错误。
- **修法**：改用私有 sentinel 文件（沙箱内只写、父进程读），或 sentinel 携带随机 token。

#### S4 — 5 处 bind 源无存在性守卫 `新发现` `中`

- **现象**：`domains/harness.py:107-113` 对 `agent_host` / `agent/` / `utils/` / `domains/__init__.py` / `domains/task_worker.py` 的 `--ro-bind`/`--bind` **无 `os.path.exists` 守卫**；仅 `.gan_runtime`（`:118-123`）是条件 bind。
- **后果**：上游拷贝清单（`task_execution.py:38-45` 的 `_RUNTIME_FILES`/`_RUNTIME_DIRS`/`_HARNESS_FILES`）与 bwrap 命令一旦不同步，bwrap 直接 `Can't find source path` 非零退出。**与 `docs/6` §6.2 记录的两个 bug 属同一类**，只是当前这几项恰好都存在。
- **修法**：统一加存在性守卫（缺文件给出可读错误），或把"拷贝清单"与"bind 清单"收敛为同一常量来源。

#### S5 — `eval_failures.jsonl` 以 `"w"` 打开 `新发现` `低`

- **现象**：`domains/harness.py:345` `open(..., "w", ...)`。
- **后果**：resume 复跑**覆盖**上次失败记录；且 `save_interval` 中途落盘（`:334-337`）只写 predictions 不写 failures，进程在最终块前被杀则失败记录不落盘。
- **修法**：改 `"a"`，并把 failures 与 predictions 同频落盘。

#### S6 — `resume_from` 越界时每题失败 `新发现` `低`

- **现象**：`resume_from` 时 `output_folder = os.path.abspath(resume_from)`（`harness.py:250`），而沙箱用 `run_root = os.path.realpath(os.getcwd())` 做包含性校验（`:141-143`、`_sandbox_path` `:36-45`）。`--resume_from` 指向 cwd 之外时，`chat_history_*.jsonl` 不在 `run_root` 下 → 抛 `ValueError` → **每题都记失败**。
- **触发**：`python -m domains.harness --dataset_root R --resume_from /abs/elsewhere`。GAN 路径恒用 `--run_id`，**不触发**。
- **修法**：统一 `abspath`/`realpath`，或对 `resume_from` 放宽包含性要求。

#### S7 — 凭证经 env 进入沙箱 `新发现` `低`

- **现象**：`domains/harness.py:155` `child_env = dict(os.environ)` 把父进程**整个环境**传给沙箱子进程，仅剔除 `GAN_DATASET_ROOT`/`PYTHONHOME`/`PYTHONPATH`/`OLDPWD` 四项（`:156-157`）→ `OPENAI_API_KEY` / `OPENAI_API_BASE` 等**经 env 进入沙箱**。
- **文档矛盾**：`docs/6` §6.4 前半句称"child 按 fix1 设计又不挂载 `.env`（**凭证不进沙箱**，正确）"，与 `harness.py:155` 矛盾（同节后文自己承认"凭证仍经父进程 env 下发"）。
- **修法**：改为白名单式 env；同时修正 §6.4 措辞。

## 2. 代际继承、反馈、恢复、审计

> 簇γ 根因：**循环本地状态（`self._last_feedback` / `_last_receipt` / `_prev_predicted` / `_prev_benchmark`）与树式父选择（parent 的 `meta`）两套语义并存**。fix1 只把 planner 切到后者。

### 2.1 未披露缺陷

#### L1 — fix1 半修：evaluator 与 digest 结算仍读循环本地 `新发现` `中`

- **已修的一半**：planner 读所选 parent 的 meta —— `loop.py:688-692`（`parent_feedback`/`parent_receipt`/`parent_predicted_score`/`parent_benchmark_score`）、`:700`（`last_feedback=parent_feedback`）、`:707`（`receipt=parent_receipt`）。
- **未修的一半**：evaluator 仍拿循环本地 —— `loop.py:772` `"receipt": self._last_receipt`、`:774` `prev_feedback={**(self._last_feedback or {}), "digest": self._last_digest}`；结算同理 —— `_settle_feedback_digest`（`loop.py:171-189`）用 `self._last_feedback` / `self._prev_predicted` / `self._prev_benchmark`。
- **后果**：当 UCB 选中的 parent ≠ 上一轮 child（`tree.branch_limit=2` 之后完全可能）时，planner 回应的是 parent 的问题，evaluator 却在评判"上一轮循环"的问题，digest 又把 parent 的 responses 与循环本地 issues 配对（`issue_id` 对不上 → 记为"silently ignored by planner"）。
- **修法**：`evaluate` 的 `prev_feedback`/`receipt` 与 `_settle_feedback_digest` 一并改读**所选 parent 的 meta**，使三个消费方语义一致。

#### A1 — 空补丁被记为"补丁被拒" `新发现` `中`

- **链路**：
  1. `gan/framework/task_runner.py:115-116`：`if task_code_commit == base_commit and task_code_commit: task_patch_rejected = "no new code commit (patch rejected or absent)"` —— 只要**没有新提交**就置该字段，**包含"本轮根本没提出补丁"这一绝大多数正常情形**；
  2. `task_runner.py:206` 写入 `child.meta["task_patch_rejected"]`；
  3. `loop.py:435` `rejected = plan_result.get("patch_rejection") or child.meta.get("task_patch_rejected")` → **恒为真**；
  4. `loop.py:469-472` 记事件 `{"type": "receipt", …, "rejected": true}` → **每代 `events.jsonl` 都报 rejected**；
  5. `receipt.py:94` + `43-58`：`_next_hint()` 对**任意非空** reason 返回兜底串 `"Fix the reported problem, then stop; do not repeat the same action."`；
  6. `receipt.py:121-122`：只要该字段非空就追加 `hint: …`（**不要求补丁曾被提出**）；
  7. `gan/roles/planner.py` 的 `plan()` 用 `render_receipt(receipt)` 注入下一轮 instruction。
- **后果**：无深改的代，planner 提示词出现 `## Previous round receipt` + `- hint: Fix the reported problem, then stop; …`，凭空暗示"有问题待修"；审计流每代记 `rejected: true`。
- **修法**：区分"未提出补丁"与"补丁被拒"（仅后者置 `task_patch_rejected`），或让 `_next_hint` 在无补丁时返回 `""`。

## 16. 附录 F：B6 实现（补丁构建失败不再歪曲语义）

**决策（用户拍板）**：① 失败单元 = **该代失败**（读取失败沿既有 B 级通道 `planner_failed`/`evaluator_failed` 标记该代，workspace 编辑保留、下一会话可重建补丁）；② 异常范围 = **全部放行**（三处 `_build_patch` 的 `except Exception: return ""` 整体移除，任何构建缺陷都显式失败）。

**落地（两处）**
1. `gan/patch.py:_read_lines(path, *, missing_ok=False)`：**文件不存在 → 合法空**（仅 `missing_ok=True` 处，即修改 diff 的 repo 侧——这是"新增文件"语义的载体，不可一刀切 raise）；**存在但读失败（权限/磁盘等 OSError）→ 抛出**——此前"读失败=当空文件"会把权限/IO 故障歪曲成整文件 add/delete diff（语义错误补丁直达 apply）。`_deletion_diff`（对刚枚举出的文件）与 workspace 侧读取均保持失败穿透。
2. `gan/roles/planner.py`（plan 与 self_improve）、`gan/roles/evaluator.py`（self_improve）三处 `_build_patch`：**移除 `except Exception: return ""`**——补丁构建失败不再冒充"合法空 patch"，异常传播 → loop 会话级宽捕获标 `planner_failed`/`evaluator_failed`（B 级，`RepoIntegrityError` 守卫照常放行更上层中断）。

**已知残留（记录，不在 B6 范围）**：空文件删除的 diff 由 difflib 表达为空串（删零字节文件无 patch）——既有行为，需 `diff --git` 形态才能表达；P2（granted 为**文件路径**时新建文件被 `if not os.path.exists(a_root): continue` 跳过）仍未修，属"新增文件静默丢失"同类，后续批次处理。

**验证**：`/tmp/ganaudit/test_b6.py` 11 断言全过（修改/删除/目录内删除/新增四种 diff 语义完好；repo 侧与 workspace 侧"存在但读失败"均抛出且失败前后补丁一致；三处 `_build_patch` 无 catch；构建出的健康补丁经 B4 `apply_patch_detail` 正常应用）；`test_frozen/test_kinship/test_domain_entry` 全绿；全仓 `py_compile` 通过。
