# 9 多域评测机制设计与对比实验

> 状态：**设计稿（未实施）**。本文只做两件事：①把 DGM-H 参照实现（`scripts/dgmh/`）的"多域评测"逐行拆开；
> ②给出 **M1–M9 九种可行机制 + A1–A3 三种 agent 拓扑**，并把它们组织成一套**可证伪的对比实验**。
> 落地顺序见 §7，冻结面与信息隔离约束见 §5。所有 `file:line` 均以当前工作树为准。

---

## 0. 摘要

1. **现状是"硬单域"，但扩展点已经预留好**：`--domains` 在四个入口（`scripts/run_gan.py` / `gan/driver.py` /
   `gan/outer_worker.py` / `gan/build.py`）被显式拒绝多值，而 `GanLoop` 构造函数收的本来就是 `List[str]`
   （`gan/framework/loop.py:120`），`Node.scores` 本来就是 `Dict[str, Any]`（`gan/framework/tree/store.py:46`），
   `DomainTaskRunner` 返回节点时已经写了 `scores={self.domain: score}`（`gan/framework/task_runner.py:341`）。
   **多域是"把已有的多域数据结构接上消费者"，不是重写。**

2. **DGM-H 的参照只有一条主线**：逐域并行评测 → 按域存分 → `valid_parent` 全有才算 → `select_parent` 跨域**算术平均**。
   这条主线有 7 个明确的、已在源码中定位的缺陷（§2.3），其中"未归一化均值"和"节点级 `run_full_eval` 被逐域 gate 互相覆盖"
   在原实现里是实打实的 bug，**不能原样照搬**。

3. **聚合函数是实验的自变量，必须落在冻结框架里**。项目已有明文约定 R9（`docs/5_v3改动.md:154-166`）：
   "对外实验协议 + 插桩 = 冻结框架/外部；evaluator 内部判据 = 自进化；二者不混在同一可编辑面"。
   把"比什么域、怎么聚合"交给可进化的 evaluator/design，等于**让被优化对象自己挑对自己有利的对照**。

4. **给出 9 种机制**，覆盖三条正交轴：标量化（M1/M2/M3）、门控（M4）、多目标（M5）、
   评测调度（M6/M7）、评测协议（M8）、反馈通道（M9）。它们不是互斥选项，而是可组合的因子。

5. **实验设计的关键红利是"离线重放"**：只要 P0 把所有域、所有代的分数持久化，就能用 `task_tree.jsonl`
   离线重放 M1–M5 的父代选择，测**选择遗憾（selection regret）**，**零 LLM 成本**。
   线上（live）实验只用来回答"切换机制后整条自进化轨迹是否变好"。

6. **现实约束**：当前只有 `paper_review` 有数据集且能跑通（`docs/5_v3改动.md:676-703`）。
   所以对比实验分三档域集合：T0 合成 fixture（离线、可复现）→ T1 `paper_review` 派生切片（同源、受控域偏移）
   → T2 真异质域（`search_arena` / `imo_grading`，需补数据集）。**在 T1 上验证机制，在 T2 上验证外部效度。**

## 2. DGM-H 参照实现：逐域评测的完整解剖（机制 E0）

DGM-H 是 `docs/7_遗留问题与待办.md:501-505` 指定的唯一参照，原文：
"每代并行逐域评测 + `get_score` 按域存取 + `valid_parent` 全有才算 + `select_parent` 跨域平均，`gl_utils.py:511`"。
以下是源码级展开。

### 2.1 数据流

```
CLI --domains a b c            (generate_loop.py:1043-1063, choices 硬编码)
  → eval_subsets = [get_domain_eval_subset(d) for d in domains]   (:1183)
  → 三个位置对齐的列表 (domains, eval_subsets, eval_samples)       (:1176-1181)
  → 每代: 一个容器; ThreadPool 逐域 eval_agent_worker                (:655-687)
        → 每域 gen_<g>/<d>_eval[_val|_test]/report.json             (gl_utils.py:65-93)
  → valid_parent = 所有域都有分 (eval_successful = all(...))        (:719-724)
  → select_parent: 每域 get_saved_score → candidates[g] = 算术平均   (gl_utils.py:511-587)
  → 每域 staging: get_saved_score ×= stagedeval_frac (未跑全量时)    (gl_utils.py:32-62)
  → 跨域聚合图: plot_progress_together (任一域 None 则整体 None)      (analysis/plot_progress.py:186-203)
```

### 2.2 五个部件

**(a) 逐域评测调度**：`domains` 里除 `polyglot` 以外的域走同一个容器 + `ThreadPoolExecutor` 并发
（`generate_loop.py:655-687`）；`polyglot` 单独走自己的 docker-per-task harness（`:58-108`）。
域与 `eval_subsets`/`eval_samples` 按 **zip 位置**配对——这正是缺陷 D1 的来源。

**(b) 按域存取**：分数不落聚合文件，只在需要时从 `<domain>_eval/report.json[score_key]` 现读
（`gl_utils.py:65-93`）；`archive.jsonl` 是**域无关**的扁平 genid 快照（`gl_utils.py:160-176`），
**没有 per-domain score map**。

**(c) validity 门**：`valid_parent = run_eval and (eval_successful or meta_patch_files is not None)`
（`generate_loop.py:719-724`），`eval_successful = all(get_score(d) is not None for d in domains)`。
语义是"**全有才算**"。

**(d) 跨域聚合**：`candidates[genid] = sum(per_domain_scores) / len(domains)`，条件是**每域非 None**
（`gl_utils.py:529-530`）。每域取 `get_saved_score(..., type="max")`，`type=max` = `max(agent, ensemble)`
（`gl_utils.py:50-59`）。**纯算术平均，无归一化。**

**(e) staged eval**：非 polyglot 的门是 `all(x is not None and x > 0)`（`:669-676`）；
polyglot 门是 `score >= 0.4`（`:64-108`）。全量跑完只置 `metadata["run_full_eval"]=True`；
未跑全量时 `get_saved_score` 把该域分数乘 `stagedeval_frac`（每域不同：0.1–0.5）。

### 2.3 七个不能照搬的缺陷（全部有行号）

| # | 缺陷 | 证据 | 对多域设计的含义 |
|---|---|---|---|
| **D1** | **三个列表错位**：`generate` 收到 polyglot 过滤后的 `domains`，却收到**未过滤**的 `eval_subsets`/`eval_samples`（`generate_loop.py:839/848, 918/926`），`zip` 在 `:658/:684` 配错 subset/样本数 | 当 `--domains polyglot paper_review` 时 paper_review 会用 `subset=""` + polyglot 的 n | 多域实现**不要用位置对齐的平行列表**；用 `{domain: config}` 字典或 per-domain 结构体 |
| **D2** | **节点级 `run_full_eval` 被逐域 gate 互相覆盖**：polyglot 的 gate 在 generate 之后 `update_node_metadata({"run_full_eval": ...})`（`:108`），会改动**别的域**的 staged 折扣 | `gl_utils.py:38-44` 是全节点消费 | **staging 状态必须是 (node, domain) 二元键** |
| **D3** | **AND 门一票否决**：staged gate（`:672-674`）与 `eval_successful`（`:719-724`）都是 `all` | 一个弱域让**所有域**跳过全量、并让节点失去 parent 资格 | 门控机制 M4 必须显式设计"逐域 gate"，而不是复用 DGM-H 的全局 AND |
| **D4** | **未归一化均值跨域不可比**：balrog 只在 `get_score` 里 `/100`（`gl_utils.py:78-83`），`get_saved_ensemble_score` 不做；`points_percentage` / `accuracy_score` / `average_fitness` 量纲不同；`stagedeval_frac` 每域 0.1–0.5；`type="max"` 还能跨量纲取 max | `docs/5_v3改动.md:67` 明文："多域 `random_guess` 不同，直接平均原始分不可比" | 直接引出机制 **M2（归一化）**；`mean_raw` 只能当基线 |
| **D5** | **`valid_parent` 实际上恒真**：`meta_patch_files` 的 CLI 默认是 `[]`（不是 `None`），`[] is not None` 为真，`or` 短路掉 `eval_successful` | `generate_loop.py:725, 1106` | 多域 validity 要**单独显式实现**，不要依赖"全有"这个默认 |
| **D6** | **`select_next_parent` 算完均值后丢弃**：可编辑的 `scripts/dgmh/select_next_parent.py:46-52` 算出跨域均值，`:65` 却 `random.choice(list(candidates))` | 与 `gl_utils.select_parent` 行为不一致 | 选择规则必须**单点定义**；对抗面（可进化文件）不能决定实验协议（R9） |
| **D7** | **ensemble 不是集成**：`scripts/dgmh/ensemble.py:36-49` 只是"选出该域历史最高分的那个 agent，复用它的预测"；`run_ensemble.py:58` 把 score key 硬编码成 `overall_accuracy`；CLI choices 只有 `search_arena/paper_review`（`utils/run_ensemble.py:72`）；**一个域不支持 ensemble 就让整轮 ensemble 关闭**（`:867/:953`） | — | ensemble 是"跨代快照选择"，不是跨域机制；多域实验里最多作为**迁移基线**（§6.3） |

### 2.4 可复用的部分

1. **按域存分 + 现读**：好处是 report.json 是唯一真源，`scores.jsonl` 只是索引（与 `gan/framework/scores.py`
   的"append-only 索引 + `report_sha` 回链"哲学一致）。
2. **`valid_parent` 全有才算**：对"极端鲁棒"取向是对的，作为 M4 的一个端点保留。
3. **每域独立 staging**：思路对，实现（节点级 flag）错——M7 会做成 `(node, domain)` 键。
4. **跨域聚合图**：`plot_progress_together` 的"任一域 None 则整体 None"是诚实做法，可直接照搬到 `analysis/`。

## 3. 设计空间：三条正交轴

多域评测不是一个开关，而是三个独立维度的组合。

### 轴 A：多域对 agent 意味着什么（拓扑）

| 变体 | 定义 | 改动面 | 风险 |
|---|---|---|---|
| **A1 单通才**（默认） | 一个 task agent / 一份 design，`task_brief` 是 N 份 brief 的拼接 | 最小：`loop.task_brief` 拼接即可 | brief 稀释；agent 可能在域间"和稀泥" |
| **A2 域条件化** | 同一 agent，但 design 带 `per_domain_prompt: {d: prompt}`，运行时按域路由 | 需要 **deep** 改 `gan/design/schema.py`（新增键 = 源码级改动），且 planner 要能编辑 | 设计面变大；planner 可以针对域作弊 |
| **A3 岛屿/专家种群** | 每域一个 task agent 实例 + 共享 meta（planner/evaluator），选择在域内进行 | 大：树结构、实例刷新、workspace 全部按域分片 | 不是"多域评测"而是"多域搜索"，成本 ×N 且需要新的交叉迁移算子 |

**建议**：主线用 A1；A3 作为对照臂（回答"通才 vs 专家，同一个 meta 层能不能同时改进两者"）；
A2 暂不做（schema 扩展属于可解冻轴，且与 M9 反馈机制耦合）。

### 轴 B：每代评测调度（预算）

| 变体 | 定义 | 成本 | 用途 |
|---|---|---|---|
| **B1 全量并行** | 每代评测全部 N 个域 | N× | 基线（DGM-H 语义） |
| **B2 阶梯** | 先小样本过所有域 → 逐域 gate → 过的才跑全量 | <N× | M7 |
| **B3 随机子域 k-of-N** | 每代只评 k 个域（无放回），聚合在子集上 | k/N× | M6；无偏但高方差 |
| **B4 轮转** | 按 genid 轮转 k 个域 | k/N× | M6 的确定性版本（无随机源时唯一可行） |

### 轴 C：跨域聚合与选择（本设计的核心）

| 子类 | 变体 |
|---|---|
| **C1 标量化** | 算术均值 / excess 均值 / 几何均值 / 最差域（max-min） |
| **C2 门控** | 全有 gate / 逐域质量下限 gate / 下限 + 均值 |
| **C3 多目标** | Pareto 非支配 + hypervolume / 逐域 UCB 求和 |
| **C4 协议** | 选择域 vs 留出域（held-out）分离 |

**M1–M9 就是这三轴的具名组合点**，下面逐个给规格。

## 4. 候选机制规格（M1–M9）

记号：域集合 `D = {d_1..d_N}`；第 g 代的域分向量 `S(g) = (S_1..S_N)`；
`r_d` = 域 d 的随机基线（report.json 的 `random_guess_accuracy`）；
`excess_d = clamp((S_d − r_d)/(1 − r_d), 0, 1)`；`valid(g)` = 节点是否有资格做父代。

每个机制给：**目标 / 规则 / 最小改动点 / 成本 / 前提 / 失效模式 / 可证伪假设**。

---

### M1 `mean_raw` — DGM-H 直搬（基线，必须实现）

- **目标**：给所有机制一个"最小惊讶"参照；也是复现 `docs/7:504` 描述语义的锚。
- **规则**：`valid(g) = ∀d: S_d(g) ≠ None`；`V(g) = (1/N)·Σ S_d(g)`；`Node.value.score = V(g)`。
- **改动点**：§1.2 的 #1–#9；`tree/store.py` 零改动（`value.score` 已聚合）。
- **成本**：N× harness；N 份 report。
- **前提**：所有域量纲可比 —— **实际上不成立**（D4）。
- **失效模式**：量纲/难度差异大的域主导均值；某域崩到随机基线以下仍被均值掩盖。
- **可证伪假设 H1**：`mean_raw` 的**最差域**分数显著低于 M2/M3；且差距随域间 `r_d` 方差增大而增大。

### M2 `excess_mean` — 归一化均值（**推荐默认**）

- **目标**：把"跨域可比"变成前提而不是假设。直接落地 `docs/5_v3改动.md:63-78` 的未实施设计。
- **规则**：
  `E_d(g) = max(0, (S_d − r_d)/(1 − r_d))`；`V(g) = (1/N)·Σ E_d(g)`；
  原始 `S_d` 照常写入 `Node.scores`（分析用），`value.score` 存 `V`。
  变体：`M2b z-score`（按域历史均值/标准差标准化）；`M2c 排名`（逐代域内排名平均，抗量纲和异常值）。
- **改动点**：M1 之上加一个纯函数聚合器（**放 `gan/framework/`，约 30 行**）+ `report.json` 读 `random_guess_accuracy`。
- **成本**：0 额外 LLM 成本。
- **前提**：`r_d` 估计可靠。`paper_review` n=100 时 `r_d` 由报告在**过滤后样本**上算出，注意小样本噪声
  （staged n=10 时 `r_d` 的 SE 可达 ~15%，这也是 M7 要"逐域 gate 而非逐域折扣"的原因）。
- **失效模式**：若某域 `r_d → 1`（二分类且标签极偏），`1 − r_d` 放大噪声 → 需要 `M2c` 兜底或设下限样本数。
- **可证伪假设 H2**：在域间 `r_d` 差异 ≥ 0.15 的域集合上，`M2` 的选择遗憾显著低于 `M1`（离线重放可直接测，§6.4）。

### M3 `max_min` — 最差域（鲁棒性端点）

- **目标**：优化"没有短板"而不是"平均好"。
- **规则**：`V(g) = min_d E_d(g)`（或 `min_d S_d`）。
- **改动点**：与 M2 同构，只是聚合函数换 `min`。
- **成本**：0。
- **前提**：域数 N 小（N≤5）；N 大时 min 会退化成"最噪声的域"。
- **失效模式**：**过度保守**——为修最差域牺牲整体，甚至卡在某个不可修复的域上无法前进。
- **可证伪假设 H3**：`M3` 显著降低"域崩溃率"（§6.5），但在平均分上付出可测代价（预期 1–3 个百分点）。

### M4 `gate_mean` — 逐域质量下限 + 均值

- **目标**：把"最差域"变成**硬约束**而不是目标函数，避免 M3 的过度保守。
- **规则**：`valid(g) = ∀d: S_d(g) ≥ τ_d`；其中 `τ_d ∈ {r_d, r_d+δ, 历史分位数 q}`；
  `V(g) = mean_d E_d(g)`。不合规的节点 `valid_parent=False`（但仍入档、仍写 scores 行、仍可被 evaluator 评估）。
- **改动点**：`loop._finalize_child` / `_finalize_invalid_node`（`loop.py:304-350`）增加逐域 gate 分支；
  **新增 `scores.jsonl` 行**以保持可审计（现有 invalid 路径已经这么做了）。
- **成本**：0 额外评测；可能浪费一整代的搜索预算（节点被弃用）。
- **前提**：`τ_d` 要有意义。用 `r_d` 当 τ 时需要 M2 同样的 `r_d` 可靠性。
- **失效模式**：`δ` 设太紧 → 早期全灭、树无候选（`_candidates` 空 → 需要 fallback，`docs/5 R5` 已讨论过"0 并列无梯度"）。
- **可证伪假设 H4**：`M4` 在**同等总预算**下早期样本效率优于 M3（用"每代有效改进次数"衡量）。

### M5 `mo_ucb` — 多目标，不标量化

- **目标**：不把 N 维压成 1 维；保住 Pareto 前沿与多样性。
- **规则**（二选一）：
  - `M5a` 逐域 UCB 求和：`metric(g) = Σ_d [ E_d(g) + c·sqrt(ln(Σchildren+1)/(children_g+1)) ]`
    —— 探索奖励共享、利用分逐域独立；
  - `M5b` Pareto 非支配 + 超体积（hypervolume）父代选择：先按 `S(g)` 求非支配集，再在集合内按超体积贡献 + 深度罚选。
- **改动点**：`tree/store.py:_metric` 需要一个"metric 钩子"（**frozen 文件改动，必须 framework-owned**），
  并且 `select_parents` 的排序要能接受"逐域向量"。
- **成本**：0 额外 LLM；计算成本可忽略（N≤10）。
- **前提**：域数 N ≤ 10；否则超体积维度灾难。
- **失效模式**：非支配集在中后期变得很大 → 选择退化成随机；需要对"超体积贡献为 0"的节点做 tie-break（现有 depth/cost penalty 可复用）。
- **可证伪假设 H5**：`M5b` 的 Pareto 前沿规模 / 超体积显著高于所有标量化机制，且**终代最差域不低于 M3**。

### M6 `rotate_k` — 随机/轮转子域

- **目标**：把每代 N× 成本降到 k×，换取更多代（open-ended 搜索通常更看重"代数"而非"每代精度"）。
- **规则**：每代抽 `k` 个域（B3 无放回随机 / B4 轮转）评测；聚合在**子集**上；
  **未评测域的分数不回填、不参与 `value.score`**（避免用陈旧值制造假梯度），但保留在 `Node.scores` 里带 `stale=True` 标记。
- **改动点**：调度层（`loop.run` 内层循环）；需要**新增随机源**（见 §6.6 的 seed 问题）。
- **成本**：k/N ×。
- **前提**：域近似可交换（exchangeable）；否则随机子域会产生**方差爆炸的选择噪声**。
- **失效模式**：k=1 且域难度差异大时，UCB 会把"抽到容易域"误当成"实力提升"——**这是本机制最危险的失效模式**，
  必须用 §6.5 的"域崩溃率"与"跨域方差"双指标监控。
- **可证伪假设 H6**：当域间难度方差小（T1 同源切片）时，`M6(k=1)` 在**等总预算**下终代平均分不低于 `M1`；
  当难度方差大（T2 异质域）时显著低于 `M1`。

### M7 `staged_per_domain` — 逐域阶梯评测

- **目标**：用便宜的短评测提前淘汰坏节点；修掉 D2/D3（节点级 flag + 全局 AND）。
- **规则**：
  - Stage-1：每域跑 `stagedeval_samples` 个样本；
  - Gate：**逐域**判断 `S_d^stage1 ≥ τ_d`；某个域不过 → 该域标 `staged_failed`，
    其余域**继续**跑全量（无跨域折扣）；
  - Stage-2：通过的域跑全量；未跑的域分数按该域 `stagedeval_frac` 折扣（DGM-H 的折扣语义保留，
    但键是 `(node, domain)`）；
  - `metadata["run_full_eval"]` 改为 `metadata["full_eval_by_domain"] = {d: bool}`（**修 D2**）。
- **改动点**：`task_runner` 的评测调用点 + `task_execution.run_harness_and_report` 的 `num_samples` 参数；
  `loop` 里读 `full_eval_by_domain` 决定是否折扣。
- **成本**：期望成本 < N×（取决于 gate 通过率）。
- **前提**：`stagedeval_samples` 足够给出可判别的分数（paper_review 默认 10 → 二分类 SE≈15%，**太吵**；
  建议机制实验里提到 30–50）。
- **失效模式**：gate 阈值基于噪声 → 好节点被误杀（假阴性）；对**方差大的域**系统性不利。
- **可证伪假设 H7**：在固定 token 预算下，`M7` 的终代平均分优于 `M1`，且 gate 的假阴性率 < 20%
  （假阴性率可由"stage-1 不过但 stage-2 全量后其实 ≥ τ"的离线计数直接测得）。

### M8 `holdout_protocol` — 留出域协议（正交协议，不替换聚合）

- **目标**：把"自我提升"与"泛化"分开度量。**仓库目前完全没有 held-out domain 概念**
  （全仓零命中，只有域内 `test_subset`）。
- **规则**：`D = D_sel ⊔ D_ho`。
  - 选择/planner/evaluator 只能看到 `D_sel` 的分数与 brief；
  - `D_ho` 的 report 照常生成、落 `runs/<genid>/<d_ho>/report.json`，但**不进入**
    `Node.value.score`、`_EVALUATOR_META_KEYS`、`planner` 的 parent summary、`feedback_digest`；
  - 仅在人类分析/报告层可见（`analysis/` 读 `scores.jsonl` 的 `role="holdout"` 行）。
- **改动点**：一个**显式投影**（正视 default-deny 约定的正确用法）：新增 `domains.holdout: [..]` 配置 +
  在 `_append_score` / `_EVALUATOR_META_KEYS` / planner parent summary 三处过滤。
- **成本**：`|D_ho|×` 评测成本，但不多花搜索预算。
- **前提**：`D_ho` 的 brief 也必须对 planner 隐藏（否则 planner 会直接优化它——
  这是"迁移"而不是"泛化"）。**这是本机制最容易实现错的一点**。
- **失效模式**：留出域被间接泄漏（例如 task agent 的 prompt 里含全部域 brief）→ 指标虚高。
- **可证伪假设 H8**：`D_sel` 上的最差域分数是 `D_ho` 得分的**更好预测子** than `D_sel` 均值
  （即 H3 的动机在留出协议下也成立）。

### M9 `evaluator_cross_domain` — 逐域反馈通道（改变反馈，不改变选择）

- **目标**：让 evaluator 的"benchmark 不可见问题"能表达成**逐域**的 issue（例如"域 B 的失败模式是过度保守"）。
- **规则**：
  - reveal 阶段把标量 `benchmark_score` 扩成 `{"per_domain": {d: S_d}, "aggregate": V}`（**显式白名单扩展**）；
  - blind 阶段的 `run_summary.report_summary` 仍是每域一份、且**继续剔除** `overall_accuracy` / `random_guess_accuracy`
    （保持 §5.2 的盲评卫生）；
  - evaluator 的 `report_issue` 增加可选 `domain` 标签；planner 的 `respond_issue` 的 `response_kind` 语义不变。
- **改动点**：`gan/roles/evaluator.py:_reveal_instruction`（`:64-76`）；`loop.py:1052` 的 `meta_view` 投影；
  `gan/summary.py:project_responses_for_evaluator` 若要把 domain 标签带给 evaluator 需显式加键。
- **成本**：evaluator 的 prompt 变长；**不改选择**，因此可与 M1–M8 任意组合。
- **前提**：严格 default-deny —— 新键不加入投影就永远不会到达 evaluator（符合现有约定）。
- **失效模式**：逐域分数进入 evaluator 后，evaluator 可能开始"拟合分数"（违反盲评精神）→
  必须保持"先盲评、后 reveal"，且 reveal 只给**客观分**不给"如何提分"。
- **可证伪假设 H9**：`M9 + M2` 相比 `M2`，在**平均分不变**的前提下降低最差域分数（反馈机制改善短板）。

---

### 4.10 A3 `islands` — 专家种群（拓扑对照，非评测机制）

- **规则**：每域一个 task agent（独立 design、独立树分支），planner/evaluator 元层共享；
  选择在域内进行，聚合分数只用于"哪个岛该多分预算"。
- **为什么放进对比实验**：它回答一个与 M1–M9 正交的问题——**"多域变差"究竟是评测聚合的问题，
  还是单通才 agent 的能力问题**。如果 A3 显著好而所有聚合机制都差，说明瓶颈在拓扑，不在聚合。
- **成本**：N× 存储与 workspace；评测成本与 A1 相同（每代仍是 N×）。

## 5. 与冻结/隔离约束的兼容性

这一节不是形式主义：项目已经因为"让被优化对象决定对照"吃过设计教训，多域评测**正好**落在那个面上。

### 5.1 R9 归属（最重要）

`docs/5_v3改动.md:154-166` 原文：
> **问题**：若让系统参与决定"比什么、怎么算"，进化可优化掉对自己不利的对照，结论不可比。
> **新设计**：**对外实验协议 + 插桩 = 冻结框架/外部**；**evaluator 内部判据 = 自进化**；二者不混在同一可编辑面。

推论（本设计的强制约束）：
- **域集合、聚合函数、gate 阈值、留出域划分、staging 样本数** → 全部写在 **`gan/framework/loop.yaml`**
  并只被 `gan/framework/` 读取（`gan/framework/*` 在 `frozen.py:81-89` 的 TRUST_ANCHOR 内，角色不可写）。
- **evaluator 的 issue 判据**（哪些问题值得报）→ 继续留在 evaluator 的可进化 design 里（那才是 self_improve 的目的）。
- **绝不允许** planner/evaluator 通过 `request_source_access` 改聚合逻辑，也绝不允许把聚合写成 evaluator 的 tool。
  `gan/components/evaluator/**` 与 `gan/registries/evaluator.json` 都在 evaluator 的可写面内
  （`frozen.py:44-50, 60-64`）——**把"多域聚合"实现成 evaluator 组件会直接违反 R9**。

### 5.2 基准标签隔离

- 现状（正确）：标签由父进程 harness 从 `repo_root` 读，**只经 CLI `--dataset_root`** 传给父 harness，
  子进程 env 里 `GAN_DATASET_ROOT` 被剔除（`AGENTS.md`；`docs/7:157`）。
- 多域推论：**每域一个独立的标签可见域**。`DomainTaskRunner` 执行第 d 域时必须只把第 d 域的
  `questions.csv` 放进 `run_dir`；否则子 agent 能看到别的域（甚至留出域）的输入。
- 留出域 D8 是新增攻击面：task agent 在 `D_sel` 上运行时，其 workspace 里**不能出现** `D_ho` 的
  questions/labels/brief。`prepare_run_dir(..., domains=[...])` 的域包并集要排除 `D_ho`。

### 5.3 盲评卫生与 planner→evaluator 隔离

- blind 阶段 `report_view` 继续剔除 `overall_accuracy` / `random_guess_accuracy`（`loop.py:1054-1055`）；
  多域后是**每域一份** `report_summary`，剔除规则逐域应用。
- reveal 阶段给 evaluator 的 `benchmark_score` 从标量变成向量——**必须显式**扩展，
  因为 `_EVALUATOR_META_KEYS`（`loop.py:57-70`）是 default-deny allowlist；
  不加入就永远到不了 evaluator（这是安全默认，不是 bug）。
- `respond_issue.feedback` 的禁令不变：**任何 `feedback` 文本的派生统计都不许进入 evaluator 投影**（`gan/summary.py:71-92`）。

### 5.4 轨迹可见性

- `AccessContext.trajectory_genids` 目前是**代际**集合（planner=父代；evaluator=当代+父代）。
  多域后需要决定：**每域一条 task 轨迹**（`trajectory/outer_<O>/<genid>/task__<d>.jsonl`）还是**一条合并轨迹**。
  - 推荐**每域一条**：轨迹归档在评估前完成（`AGENTS.md`），合并会丢失域归属，而 M9 恰恰需要域归属；
  - 代价：`paths.session_traj_file` 需要一个 `suffix`/`domain` 参数（frozen 文件改动）；
    `trajectory.py` 的脱敏规则逐域应用（脱敏是信任锚，不能被削弱）。

### 5.5 访问白名单与成本

- `domains.yaml` / `loop.yaml` 冻结 → 新增域、调聚合参数都是**实验者的框架编辑**，不是 run 内行为。符合 R9。
- 成本：N× 评测 + 每域一份 report + 每域一条轨迹；`loop.yaml` 的 `cost.*` 仍是 RESERVED 无消费者
  （`docs/7 §4`，G3/B21）。**多域实验必须自己做成本核算**（§6.6），否则 N× 成本会把任何跨机制比较污染成
  "谁跑得多谁赢"。

## 6. 对比实验设计

### 6.1 研究问题

| RQ | 问题 | 主要对照 |
|---|---|---|
| **RQ1** | 跨域聚合函数如何影响**选择质量**（在固定节点池上）？ | M1 vs M2 vs M3 vs M4（离线重放） |
| **RQ2** | 在**等总预算**下，调度（M6/M7）能否追平甚至超过全量评测？ | M1 vs M6(k=1,2) vs M7 |
| **RQ3** | 多目标是收益还是噪声？ | M5b vs M2 |
| **RQ4** | 单通才（A1）vs 专家岛屿（A3），瓶颈在哪一层？ | A1+M2 vs A3+M2 |
| **RQ5** | 留出域上的泛化能否被选择域指标预测？逐域反馈（M9）是否改善短板？ | M8 / M9 开 vs 关 |
| **RQ6** | `task_brief` 拼接是否稀释单域性能？ | 单域基线 A0 vs 多域 A1+M2 |

### 6.2 域集合的三档构建（现实约束驱动）

**硬约束**：当前只有 `paper_review` 有数据集（`domains/paper_review/dataset_filtered_100_{train,val,test}.csv`）；
`search_arena` 只有 `dataset_filtered_100_ids.json`（要 HF 下载 `lmarena-ai/search-arena-v1-7k` 重建
`dataset.csv`/`dataset_filtered.csv`）；`imo_*` 需要生成 `gradingbench_<subset>.csv`；
`polyglot` 不在 `domains.harness` 的 choices 里，GAN 的 `DomainTaskRunner` 无法驱动
（`docs/5_v3改动.md:676-703`）。所以：

| 档 | 域构造 | 目的 | 成本 |
|---|---|---|---|
| **T0 fixture** | 3 个 `domains/mdfix_{a,b,c}/`：极小的 csv（如 40 题）、`utils.py`、确定性标签；在 `domains.yaml` 注册；各配 `task_brief`/`output_contract` | **机制单测与大量重复**：可离线、可复现、可按需注入"域崩溃""域量纲不同""随机基线不同" | 极低 |
| **T1 派生切片** | 从 `paper_review/dataset.csv`（711 行）切出 `paper_review_a/b/c`：按长度分位、按标题/摘要关键词、或**按 accept:reject 先验**（50:50 / 30:70 / 70:30）。每域各自 `curate_subsets.py` 生成 `_filtered_100_{train,val,test}` | **受控域偏移**：真标签、可复现、能精确控制 `r_d` 差异（先验偏移直接改 `random_guess_accuracy`） | 低 |
| **T2 真异质** | `search_arena`（HF 下载 + 重建）与 `imo_grading`（生成 csv）；两者 score_key 同为 `overall_accuracy` 但任务语义/答案空间完全不同 | **外部效度**：检验 M2 的归一化是否在真异质域上仍然必要 | 中 |

**注意**：T1 的切片**共享底层语料**，是"合成域偏移（SDS）"而不是独立域。
所有 T1 结论必须标注"受控偏移"，只有 T2 能支持"跨域泛化"的外部结论。

**域集合的具体配置建议**（每域都在 `domains.yaml` 里显式声明，因为它是冻结的注册表）：

```yaml
# 仅为实验新增；domains.yaml 由实验者在 run 之前编辑（R9：协议在框架/外部）
paper_review_a: {score_key: overall_accuracy, splits: [train, val],
                 eval_subset: _filtered_100_train, has_val_subset: true,
                 task_brief: "...", output_contract: {kind: label, allowed_labels: [accept, reject]}}
paper_review_b: {...}   # 30:70 先验
paper_review_c: {...}   # 70:30 先验
```

### 6.3 因子与实验臂

**自变量**：`{聚合} × {调度} × {拓扑} × {协议}`。

### 6.4 两阶段实验：离线重放（便宜、高功效）+ 线上（贵、看全轨迹）

这是本设计最重要的方法学设计，直接利用 §1.3 的"免费"持久化能力。

**(1) E-offline（选择遗憾重放）**
- 前提埋点：P0 就必须把**所有域**的分数写进 `Node.scores` 与 `scores.jsonl`（不能只写聚合值）。
- 做法：跑**一次**多域全量 run（例如 A2），得到一棵 `task_tree.jsonl`；
  然后**离线**对同一个节点池，用 M1/M2/M3/M4/M5 分别重算每个候选的聚合值并重放父代选择，
  度量**选择遗憾** `regret = oracle_agg − agg(chosen)`（oracle = 节点池里聚合值最大的节点），
  以及**"被选中父代在其子代上的真实表现"**。
- 优势：**零 LLM 成本、完全确定性、无噪声**；直接隔离"聚合函数"这一个变量（RQ1）。
- 注意：它测的是**选择质量**，不是**搜索质量**——所以不能替代线上实验，只能回答 RQ1/H2/H3。
- 交付物：`scripts/local/replay_aggregators.py`（本地脚本，gitignored）或 `analysis/` 下的分析脚本。

**(2) E-online（活体对比）**
- 每个臂真实驱动 loop（机制生效），比较整条轨迹的终态与效率（RQ2–RQ6）。
- 成本：N× 域 × 代数；在 T1（3 域、num_samples=100）上单臂约 3× 单域成本。

### 6.5 指标

| 类别 | 指标 | 定义 / 来源 |
|---|---|---|
| 选择质量 | **选择遗憾** | §6.4(1)；离线可测 |
| 终态 | 平均域分 `mean_d S_d`、**最差域** `min_d S_d`、**excess 均值** | `scores.jsonl` / `task_tree.jsonl` |
| 泛化 | **留出域分**、**泛化间隙** `mean(D_sel) − mean(D_ho)` | M8 专用；只在报告层可见 |
| 鲁棒性 | **域崩溃率** = `#{run,domain: final_d < initial_d − δ}` / `N·R`；**跨域方差** `Var_d(S_d)` | 需要每域初始分 |
| 效率 | 终态指标随**域评测次数** / **代数** / **墙钟** / **token** 的曲线 | 成本对齐的核心 |
| 成本 | 每域 harness 调用数、`num_samples` 总量、wallclock；token 待 G3 | `cost.*` 目前 RESERVED |
| 过程 | evaluator 盲评误差 `|predicted − benchmark|`（逐域）、每域 issue 数、patch 接受率、`score_status` 分布 | `packet.json` / `events.jsonl` |
| 多样性 | Pareto 前沿规模 / 超体积（M5）；树的分支广度 | `task_tree.jsonl` |

**主指标**（预先指定，避免 p-hacking）：**等总预算下终代的 `min_d E_d`（最差域 excess 均值）**。
理由：它同时惩罚"平均好但崩一域"（M1 的病）和"过保守"（M3 的病），且跨域可比。

### 6.6 预算与随机性（必须显式处理的两个坑）

**坑 1：成本 ×N。** 三种对齐口径，必须选一个当主口径并全部报告：
- (a) **等代数**（每臂同样代数）：多域机制天然贵，只适合回答"机制本身的排序"；
- (b) **等域评测次数**：把总评测次数固定，M6/M7 可以换到更多代数；
- (c) **等 token/墙钟**：最公平，但依赖 G3 成本闭环（未接线）。
建议：**主口径 (b) 等域评测次数**（可离线精确计数），(a)/(c) 作为敏感性分析。

**坑 2：仓库当前没有任何随机源。** `docs/6_v5改动.md:45-62` 明确记录：`GAN_SEED` 是装饰，
"整个 loop 没有任何随机源"，UCB 并列由 `sorted` 稳定性决定，选择确定性。
所以：
- **不带随机的机制（M1–M5、M7、M8、M9）**：一次 run 就是一次确定性结果的副本，
  **重复性必须来自数据/域划分**（不同的 `_filtered_100_train` 抽取）或不同的初始 subset。
- **带随机的机制（M6 的 B3 随机子域）**：必须**新增一个消费者存在的 seed 键**
  （例如 `loop.selection_seed`，写进 `loop.yaml` 并被 `loop`/`tree` 读取；符合 `loop.yaml` 头部
  "每个键必须有 `cfg.get` 消费者"的规则）。否则 M6 不可复现，结论不可信。
- **建议副本设计**：T1 用 5 个不相交的 100 样本抽取（`_filtered_100_train_s0..s4`），
  每个臂 × 每个副本 = 一次 run；T0 用 10+ 个 fixture 变体做机制单测；T2 因成本降为 3 个抽取。

### 6.7 统计与判定

- **配对**：同一副本 seed / 同一域划分下比较各臂（paired）。
- **检验**：副本数 R=5 时用 Wilcoxon 符号秩检验（配对、非参数）；R≥8 时可加混合效应模型
  （固定效应=机制，随机效应=副本）。
- **功效**：paper_review n=100 二分类，`overall_accuracy` 的 SE ≈ 5%（p=0.5）。
  R=5 个副本使**均值**的 SE ≈ 2.2%，即可检出 ~5–7% 的配对差异（80% 功效）。
  若要看 1–3% 的效应（M3 的"可测代价"），需要 R≥10 或把每域样本提到 200+。
- **多重比较**：主指标只做一次检验（A1 vs A2）；其余为探索性，报告效应量 + 置信区间，不做"显著性打猎"。
- **效应量**：报告 Cliff's delta 或配对均值差及其 95% CI。

### 6.8 预注册的可证伪假设

| # | 假设 | 判定实验 | 反证条件 |

## 8. 风险与未决问题

1. **域构造的效度**：T1 切片共享语料，"域"不是真独立。所有 T1 结论只能声称"受控偏移下的机制排序"，
   外部结论必须等 T2。**这是本设计最大的效度威胁。**
2. **`r_d` 的可靠性**：M2/M4 都依赖 `random_guess_accuracy`。在 staged 小样本（n=10）上，
   `r_d` 的噪声足以翻转选择。建议 staged 样本提到 30–50，或对 `r_d` 用全量样本的固定值（**不随代变化**）。
3. **成本 ×N 与 `cost.*` 未接线**：等 token 口径在 G3 之前做不到；只能先用"域评测次数"近似。
4. **无 seed 轴**：M1–M5/M7–M9 的重复只能靠数据副本，这限制了可检出的效应量。
   若研究结论对 1–3% 的效应敏感，需要先补 seed 或大幅增加副本。
5. **M8 的泄漏**：留出域 brief 对 planner 的隐藏是最容易漏的一步；必须有自动化断言
   （类似 `scripts/local/test_frozen.py` 的"投影不含 holdout 键"检查）。
6. **A3 与"多域评测"的边界**：岛屿拓扑会改变树/选择语义，可能把 RQ1/RQ2 的结论污染成"拓扑效应"。
   建议 A3 只在 T1 上跑、且与 A1–A7 分开报告。
7. **未决**：`Node.value.score` 之外是否需要保留"聚合函数名"进 meta（可审计性 vs 冗余）？
   建议写 `meta["aggregate"] = {name, per_domain}`，因为离线重放要靠它区分"当时用的规则"。
8. **未决**：多域后 `stagnation` 判据（`loop.py:1130-1131` 的 `cs - ps`）用聚合分还是逐域分？
   建议聚合分（与选择一致），但**逐域改善也要进事件**，否则"平均不动但某域改善"会被判成停滞。
