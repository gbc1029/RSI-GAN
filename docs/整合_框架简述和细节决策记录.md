## 1. 框架简述

> 依据 docs/2（总体方案）、docs/3（深入设计 + v5 勘误对照）、docs/4（v2/v3 落地）、docs/5（v4）、docs/6（v5）。docs/3 §0–§7 为 v1 旧架构描述，旧名/旧路径以 docs/3 L63–71 勘误对照表为准（`gan/operators/*`→`gan/tools|registries`、`code_edit`→`deep/request_source_access`、`mint_operator`/`eval_points.yaml`/`composer.py`/`shared/memory` 已删除、`gan/loop.py` 等→`gan/framework/*`、模型仅由 `models.yaml` 经 `--model` 显式传参）。

### 1.1 定位与三角色（docs/2）
- RSI-GAN：在 HyperAgents(DGM-H) 基座上加三层自进化，GAN 式三角色——**planner=生成器**（改 task agent），**evaluator=判别器**（评 task agent），**task agent=生成物**（被进化对象，即 `task_agent.py`）。
- planner/evaluator 均有**自进化**（自修改=改自身设计/提示词/组件，而非"他者"模式的 HyperAgent）；两者各自持独立版本树与独立奖励。
- 端到端验证域 paper_review 先行（数据在仓库内、无镜像依赖；polyglot 需评测镜像，延后）。

### 1.2 双循环与调度（docs/2 §1/§2.2，docs/3 §1，docs/5 V4.4）
- 外循环一轮 = planner.self_improve + evaluator.self_improve（元层一代，两角色各自推进元层树）；内循环一轮 = task agent 一代：选父代 → planner.plan → task_runner 执行评测 → evaluator.evaluate（盲评→揭示）→ 建包/结算 → commit 节点 + 停滞判定。
- 触发外循环：内循环预算用尽 / 连续停滞 / hard_failure（设计口径；hard_failure 触发机制未实现——docs/6 §二 R2 决策硬失败不中断内循环，见 §2.14）。
- **调度为单链**（v4.4 决策）：planner/evaluator 无 accept/reject、无父代选择；每个 outer 从上一 checkpoint 的设计续跑，`outer_improved` 只记录不强制；同一 outer 内两角色 self-improve 会话并行（写面按席位不相交）。

### 1.3 设计-算子-工具体系（docs/3 v2/v3 节，docs/4 §9/§10，docs/5 V4.3）
- 每个角色的"浅层设计"= 单一 config JSON（`gan/design/`，schema 极小 + seeds 种子）；浅层算子只可改**已有键**、改**已声明动态键**（声明与消费者同补丁进退）、增删**已注册组件**的选择。
- 激活规则：**always-on → `gan/tools/`**（work/<role>、work/common、design/、deep/），**opt-in → `gan/components/`**（注册表登记 + 设计 config 选择）。注册表 = 每角色单写者 json（task/planner/evaluator）。
- 深层修改统一经门控 `request_source_access`（view/modify）+ `register/unregister/update_component`；无 `mint_operator`（v4.3 移除）。**planner/evaluator 不给裸 bash**（不可 confined，V4.13/沙箱暂缓决策）。
- 身份契约：注册名 = 模块文件名 = `tool_info()["name"]`（第三者由运行时装载门强制，第 22 批起）。

### 1.4 隔离与访问边界（docs/2 §2.4/§2.6，docs/3 §4，docs/5 V4.10/4.15，docs/6）
- 四层隔离：修改深度门控（默认面=配置+算子；源码需声明）、工作区隔离（按角色实例分目录、授权前工作区无源码 → 真隔离）、信息隔离（planner↔evaluator 互不可见，仅结构化投影）、审计（grant/事件/修改深度记录）。
- 访问 allowlist 冻结于 `frozen.py`：task 无权限；planner 读+写 t∪p；evaluator 读 t（只读）+读写 e；其余默认冻结、无持久化 deny list。写权限进一步按**会话席位**（role+seat）限定（第 15 批登记 S 族）。
- P→E 信息流为**具名投影**（default-deny）：diff 摘要、receipt 投影、meta 投影、feedback digest 均只过结构化事实；planner 自由文本（rationale/reason/feedback）不进 evaluator 决策面。
- 任务运行与 repo_root 隔离：每代在 `work/<genid>/repo` 最小允许清单副本内跑；基准标签只经 CLI `--dataset_root` 从 repo_root 传入，不进子进程 env。

### 1.5 版本管理与代码血统（docs/3 §3，docs/5 V4.5/V4.17，docs/6 线 7）
- 三棵树（task/planner/evaluator）JSONL 事件回放；task 树限分叉/深度；节点价值 = score + potential（盲评，不进选择公式，防对抗污染）+ cost（预留）。
- 父代选择：latest/best/ucb（默认，含深度/成本惩罚）；停滞 patience 触发 break。
- v5 起 **branch-per-node 代码血统**：每代代码 = per-run git 树（`ckpt/code`）中的一个 commit，git 父 = 被选父代的 commit；每代固定 ref `task_<genid>`，outer 入口 HEAD 固定 `outer_<O>_base`；规划/打补丁的 base 一律从父代 ref 解析（不追 HEAD）；被拒/缺补丁的代别名为父代 commit（无血统空洞）。
- driver 模式：`scripts/run_gan.py` 物化 per-run git 树，每个 outer 一个 `gan.outer_worker` 子进程（cwd/PYTHONPATH=code_root），角色自改对下一 outer 生效；task 深补丁与角色自补丁均"校验+提交"进代码树。

### 1.6 奖励与反馈（docs/2 §2.3，docs/3 §5，docs/4 §3/§9）
- evaluator 反馈为**文字 digest**（v2 起去数值化）：`build_feedback_digest` 逐条 issue→planner 回应→修复判定+证据；盲评协议（先盲评 `predicted_score`，再揭示 benchmark 深评）用于校准，evaluator 不拟合 benchmark 分。
- 2×2 矩阵（接纳×修复）在 v2 后仅产出**诊断标签**（数值权重已删）；`judge_fix` 要求证据，"是否修复"由 evaluator 从轨迹/代码判断。
- 外循环 evaluator 定位：找 benchmark 看不见的问题（过程评价/作弊检查/细节问题），目标是"评判准确有用"而非分数。

### 1.7 输出布局与持久化（docs/5 V4.5/V4.15，docs/6 F5/G2）
- 布局单一来源 `gan/framework/paths.py`：`ckpt/`（checkpoint + code 树 + design）、`logs/`（events.jsonl 等）、`trajectory/outer_<O>/`、`scores/scores.jsonl`、`runs/<genid>/`（小证据：packet/eval/feedback_digest/patch_receipt/diff）、`work/<genid>/`（临时，会清理）、`workspaces/<role>/outer_<O>/`。
- checkpoint：`ckpt/checkpoint.json` 原子覆盖为最新；outer 边界另写不可变 `ckpt/outer_<N>.json`（同 outer 重跑归档为带毫秒后缀，F5 混合式）；日志只追加不截断（`op=reset` 事件）。
- trajectory：全 JSONL，按实例分文件；归档+脱敏（redaction 属冻结信任锚）；可见集合由 `AccessContext.trajectory_genids` 每会话显式给定（v4.20）。

### 1.8 模型配置与运行（docs/5 附：模型配置统一管理，docs/6）
- 模型单一来源 `gan/framework/models.yaml`，仅被 `models.py` 纯查表读取：无 env、无 fallback、无优先级链；条目 = 模型串或 `{model, reasoning_effort}` 映射；`reasoning_effort` 为网关思考强度档（low|high|max），全程显式传参不走 env。
- 运行入口 `python scripts/run_gan.py --domains ... --subset ... --outer N --inner M`；域任务 agent 与 driver 共用 task 模型，经 `domains.harness --model` 显式传入。
- 环境事实（docs/1）：受限企业网（aTrust）下依赖清华镜像/gh-proxy；GPU 容器 `hyperagents:base` 可用；API 走 OpenAI 兼容端点（`.env`）。

### 1.9 与 DGM-H 基座的关系（docs/2 §3.1/§2.8，docs/4；scripts/dgmh 迁移见 docs/5）
- 复用基座：AgentSystem + chat_with_agent 文本协议工具循环、harness/report 评测管线、gl_utils/git_utils/docker_utils；DGM-H 原入口脚本移至 `scripts/dgmh/`。
- 差异：修改者=自身（自进化），evaluator 为全新 agent 形态角色；GAN 框架代码集中在 `gan/`，基座仅最小适配（模型注入点、tools_dir、域配置注册表化、usage hook、RateLimitError backoff）。

## 2. 细节决策记录（按主题）

### 2.1 部署与环境（docs/1）
- 受限网络（深信服 aTrust）为一切部署/评测工作的前置约束：WSL 无 TCP 出站；镜像/依赖走清华源 + gh-proxy（**不支持 git clone 智能协议，仅 release/archive tarball**）。（docs/1 L24-35,117）
- 容器镜像 `hyperagents:base` 由"补丁版 Dockerfile"构建：跳过 git+ 依赖、proofgrader、balrog post_install → **balrog/genesis/imo 领域在容器/venv 不可用**；`Dockerfile.orig` 留底以便网络放开后还原。（docs/1 L63-76）
- LLM 接入走 OpenAI 兼容端点（`.env`）；glm-4.7-flash 为推理模型（`max_tokens` 须足额，管线 16384 够）；Zhipu 429 限流 → backoff 增补 `RateLimitError`（外部条件非管线缺陷）；litellm 1.74.9 返回 `ModelResponse` 实测兼容。（docs/1 L131-182）
- paper_review 的 `MODEL` 改 `gpt-4o-mini` 是唯一模型配置改动（匹配 az.gptplus5.com 代理）。（docs/1 L192,221）
- polyglot 实评测需 Docker Hub 语言镜像（受网络/限流未构建）——多域评测的硬边界。（docs/1 L128-129,178-180）
- 完整 `generate_loop` 编排未跑（用户决策"到此为止"，2026-09-13）；两大核心机制（task-agent 评测、meta-agent 改写）已验证跑通。（docs/1 L213-215）

### 2.2 版本管理与代码血统
- 节点价值三元组：score（确定性客观分）+ potential（evaluator 盲评分，**只破平局/进上下文，不进选择公式**——防对抗污染）+ cost（token/墙钟，字段预留）。（docs/2 L67、docs/3 L233-236）
- 树约束：task 树限分叉/深度；停滞 patience 触发 break 并 `mark_stagnant` 禁选。（docs/2 L65、docs/3 L244）
- 父代选择 latest/best/ucb（默认 UCB，含深度/成本惩罚）。（docs/3 L240-243）
- 【v2】版本管理升级 DAG：`Node.parents` 多父、`select_parents(k)`；**交叉只作用于浅层设计（config 合并），源码不三路合并**。（docs/3 L14-16、docs/4 L287）
- 配置血统：`child.meta["config_dict"]` 沿树回溯；补丁血统 prev/curr_patch_files。（docs/3 L247-249）

### 2.3 修改深度与源码门控
