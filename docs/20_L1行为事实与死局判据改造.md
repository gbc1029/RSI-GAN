## 1. 范围与目标

三件事，一条主线：**让"agent 在转圈还是干活"这件事在框架里可测、可判、可解释，但不给角色下处方。**

| # | 改动 | 目的 |
|---|---|---|
| A | L1 增加**动作类别占比**（转向/前进/动手） | 让 evaluator 一眼看出行为构成（证据） |

## 2. 实测依据（为什么必须改）

数据来自归档轨迹离线重算（重算的 `obs_repeat_steps` 与报告逐代一致：A1 gen0=280、A0 gen8=52、A0 gen10=142，解析器可信）。

### 2.1 现有第二个信号方向是反的

| 臂 | `obs_repeat_step_share ≥ 0.35` 触发 | 实际取值 |
|---|---|---|
| A1（最好，留出 3/5 六次不变） | **12/12 全触发** | 0.366 – 0.533 |
| A0（完整机制） | **0/8 从不触发** | 0.054 – 0.333 |

根因：`_obs_state_key` 含**朝向**，`turn left` 必然改变状态 ⇒ 转圈的人"没改变世界"的步数≈0。它量的是**信息增量**，不是进展。

### 2.2 "白费步数"类计数在健康臂上更高（所以不能当缺陷）

| 代 | 解出 | 撞墙前进 | 交互失败（抓空/白开） |
|---|---|---|---|
| A1 gen2 | 6/10 | 139 | 158 |
| A1 gen5 | 4/10 | 164 | 181 |
| A0 gen8 | 1/10 | 20 | 14 |

尝试越多、失败越多 ⇒ 任何"无效果步数"计数单独作判据都会把好 agent 判坏。

### 2.3 换成"循环检测"后方向恢复（31 代标定）

单局退化门槛 `revisit_share ≥ 0.80`，代级 `episodes_degenerate_revisit_share`：

| 臂 | degShare 范围 | 阈值 0.40 触发 |
|---|---|---|
| A1（12 代） | 0 – 20% | **0/12**（零误报） |
| A0（8 代） | 10 – 70% | 6/8 —— 漏掉的恰是它最好的 gen5(0.2)、gen7(0.1) |
| A2（11 代） | 10 – 60% | 2/11 —— 命中的恰是它最差的 gen9、gen10（各 3/10） |

对照 `zero_displacement_share ≥ 0.50`：A0 只中 3/8（gen0/4/8），A1 零误报。两个信号互补：前者抓"没离开原地"，后者抓"绕圈子"。

## 4. 详细设计

### 4.1 动作类别占比（L1 证据）

**声明**（域自己说，框架不硬编码）：

```yaml
# balrog_babyai
output_contract:
  kind: action
  allowed_labels: ["turn left", "turn right", "go forward", "pick up", "drop", "toggle"]
  action_classes:
    turn:     ["turn left", "turn right"]
    forward:  ["go forward"]
    interact: ["pick up", "drop", "toggle"]

# balrog_babaisai（无"转向"概念：四个方向是绝对移动）
output_contract:
  kind: action
  allowed_labels: ["idle", "up", "right", "down", "left"]
  action_classes:
    move: ["up", "down", "left", "right"]
    idle: ["idle"]
```

**校验**：`action_classes` 的并集必须**恰好等于** `allowed_labels`，且类间不相交；违反即 refuse（与 `output_contract` 现有 fail-closed 风格一致）。离线守卫 `scripts/local/verify_env_contract.py` 增加这两条断言。

**派生位置**：`gan/framework/task_execution.py: compute_report_summary`（框架侧，已有 `action_distribution` 与域声明，无需新的 CLI/env 透传）：

```
behavior.action_class_shares = {"turn": 0.28, "forward": 0.57, "interact": 0.15}
```

只在 `contract.kind == "action"` 且 `action_classes` 存在时出现；否则字段缺省（不写 0）。

**可见性**：`behavior` 已在 `_report_view_for_evaluator` 的放行集中（`_SENSITIVE` 只屏蔽 `label_distribution` 等），所以 evaluator 自动可见，无需新增投影。

### 4.2 循环检测（替换 `repeat`）

**单局**（`domains/balrog/evaluator.py`）：

- `_play_episode` 增加 `actions = []`，与 `state_keys` 同步 append `executed`；
- `_behaviour_summary(state_keys, actions, num_steps)` 新增：

| 字段 | 定义 |
|---|---|
| `revisit_steps` | 本局中，`(state_key, action)` 组合**在本局更早出现过**的步数 |
| `revisit_share` | `revisit_steps / num_steps` |
| `no_progress_action_counts` | 状态未变的那一步按**已执行动作**计数（`{action: n}`），供框架侧按类拆分 |

保留现有 `distinct_obs_states` / `obs_repeat_steps` / `zero_displacement`（纯增量，不改语义）。

**代级**（`domains/balrog/utils.py`）：

| 字段 | 定义 |
|---|---|
| `revisit_step_share` | Σ `revisit_steps` / Σ steps（仅统计有轨迹的局） |
| `episodes_degenerate_revisit` | `revisit_share ≥ 0.80` 的局数 |
| `episodes_degenerate_revisit_share` | 上者 / 有轨迹的局数（分母同 `zero_displacement_share`，aborted 局不进分母） |
| `no_progress_action_counts` | 各局合并后的 `{action: n}` |

**为什么是循环而不是停滞**：转圈的人每 4 步回到同一个 `(状态, turn left)` 对 ⇒ 被抓；健康 agent 尝试失败但**状态是新的** ⇒ 不计入。

> **补注（阶段 2 发现并修正）**：`no_progress_action_counts` 最初把"观测没变"的一步记在
> `actions[i]` 上，而 `state_keys[i]` 是**动作 `i` 之前**的观测，所以真正造成"没变"的是
> `actions[i-1]`。实测后果：307 个无进展步里有 48 个被记到 `turn` 上，而转向按构造不可能
> 不改变状态（朝向就是状态的一部分）。修正后三代均为 0 个 turn 归因，总数不变
> （307 / 367 / 334），只是归因换了位置。`test_behaviour_facts.py` 已加反向断言：
> `["A","A","B"] + ["go forward","turn left","go forward"]` 必须报
> `{"go forward": 1}`。`revisit_*` 与 `obs_repeat_steps` 不涉及归因，不受影响。

### 4.3 checker：只做裁判与闸门

`gan/framework/issue_checks.py: _chk_dead_end`

```
信号一（不变）：zero_displacement_share ≥ issues.check.dead_end_share (0.50)
信号二（新）：  episodes_degenerate_revisit_share ≥ issues.check.dead_end_revisit_share (0.40)
任一命中 → PRESENT；两者都缺 → UNKNOWN；缺一个 → 只用存在的那一个（缺的绝不当作 ABSENT）
metric 里继续输出 obs_repeat_step_share / revisit_step_share / episodes_degenerate_revisit_share（报告项，不进判决）
```

`DEFAULT_PARAMS`：删 `dead_end_repeat_share`，增 `dead_end_revisit_share: 0.40`、`degenerate_revisit_share: 0.80`。
`loop.py: issue_check_params` 与 `loop.yaml: issues.check.*` 同步这两项。

**升级闸门不用改代码**：`gan/design/seeds/planner.md` 规则 4b 已按「同一 `issue_key` 连续两轮 `judged_unfixed`」触发；本批只是让那项判决的**真值**由正确的 checker 给出，闸门的输入变准了。

**不给处方**：checker 仍只输出 PRESENT/ABSENT/UNKNOWN。供 planner 诊断的证据是 §4.1 的类别占比 + §4.2 的 `no_progress_action_counts`（例如"无效前进 20 次 / 无效交互 14 次"），写进 `behavior`，由 evaluator 引用——不新增任何"建议改法"的通道。

## 5. 兼容性

| 情形 | 行为 |
|---|---|
| 旧报告（无 `revisit_*`） | 第二信号不参与，只用 `zero_displacement`；不会因此被判 ABSENT |
| 非 episode 域 | 无 `behavior` → UNKNOWN（不变） |
| `balrog_babaisai` | 类别名为 `move`/`idle`；本批不适用"转向"判据（第二信号同样可用，因为它是域无关的） |
| `analysis/*` 离线工具 | 只读 score，不受影响；`scripts/local/` 的自用分析脚本需同步新字段名 |
| 回滚 | 只动度量与一个 checker 的两个分支；`fitness.w2` / 词表 / seed 不动，回滚 = 恢复 `_chk_dead_end` 的旧分支 |

## 6. 风险

1. **阈值是事后标定的**（同一批 3 臂数据）。`dead_end_repeat_share=0.35` 翻车就是这个原因。缓解：§7.4 的复跑验收为**硬门槛**，A1 出现一次 PRESENT 即视为不通过。
2. `0.80` 单局门槛把"长走廊里合理重复"的局也算退化。缓解：只在**代级占比 ≥0.40** 时才判，且 A1 实测最大 0.20，留有余量。
3. 类别划分把域知识写进 frozen 配置 —— 这是有意的（与 `allowed_labels` 同源、可离线校验），但**新增域必须同时声明**，否则占比字段缺省（不报错，只是没有证据）。

## 8. 工作分解（分阶段上线，判决与度量分离）

采用「先度量、后判决」的两步走（决策 D1）：阈值 `0.40` 是同一批数据事后标定的，不能拿它再当验收。

| 阶段 | 内容 | 行为影响 | 验收 |
|---|---|---|---|
| **1. 度量** | §4.2 循环检测 + §4.1 `action_classes` 与占比 + `no_progress_action_counts`（撞墙/抓空分型） | **零**（只多写报告字段） | 单测 + 域守卫 + 归档回放（数字必须复现 46.8% / 90.9%） |
| **2. 校准** | 跑 A1（1 臂 × 3 代）产出**新数据**，离线看新字段分布，据此定 `dead_end_revisit_share` | 零 | 用户启动；A1 的 `episodes_degenerate_revisit_share` 实测值决定阈值 |
| **3. 判决** | §4.3 `_chk_dead_end` 换信号 + `loop.yaml`/`loop.py` 透传 + 回放测试 | 改变 `process.dead-end` 真值 | 回放 31 代：A1 零触发、A0 gen4/gen8 触发 |
| **4. 复验（硬门槛）** | A0 + A1 各 3–4 代真跑 | — | A1 出现**任何一次** PRESENT 即不通过 |

阶段 1 与 3 之间必须夹着阶段 2：**阈值只能来自没见过的新数据**。

## 9. 已确认决策（2026-11-17）
| # | 决策 | 理由 |
|---|---|---|
| **D1** | 采用「先度量 → 跑 A1 校准 → 再上判决」（§8 分阶段） | 避免重演 `dead_end_repeat_share=0.35` 的"用同一批数据既证明又定参" |
| **D2** | `blocked_forward` / `failed_interaction` **进阶段 1** | 与循环检测处于同一 per-step 循环，一次改动；是 planner 诊断"撞墙还是抓空"的唯一证据（不是处方） |
| **D3** | **不新增** `policy.no-interaction` 一类 issue key | 实测反例：A2 有几代 interaction 仅 7% 仍解出 5–6/10，`issue_key` 化会制造误报并被升级闸门放大 |
| **D4** | 类别名**按域声明**：babyai `turn/forward/interact`；babaisai `move/idle` | 这三个数不参与判决（判决用域无关的 revisit / zero_displacement），硬统一会让 babaisai 的"动手占比"恒为 0，等于数字撒谎 |

**D2/D4 的落地含义**：`action_classes` 是 `allowed_labels` 的划分，必须在 `domains.yaml` 里显式声明并通过分区校验；未声明的域不产出占比字段（缺省而非 0）。

③ 撞墙/抓空分型可用 ✓；④ 占比字段逐代进入框架侧 `report_summary` ✓。

**两个必须记住的结论**：

1. **`turn` 占比不能当"转圈"的判据。** A0 gen1 转向占 62.7%（远高于 A1 的 16–26%），却解出 **6/10**、
   `deg` 只有 0.2——它在大量转向的同时仍在动手（interact 7.5%）。给阶段 4 写第一版验收脚本时
   我拿 `turn ≥ 0.60` 当触发条件，直接误报了它。真正的退化信号是**循环退化占比**：
   A0 gen0 的 0.90 对应 2/10，gen1 的 0.20 对应 6/10。（与 `obs_repeat_step_share` 那次翻车同型：
   动作构成量的是"在干什么"，不是"有没有进展"。）
2. **A0 的"停止动手"现在可见了**：interact 0.2% / 7.5% / 5.4% 对 A1 的 24–33%。
   这是旧度量下完全看不见的一类失败（`zero_displacement` 只能说"没走动"，说不了"没在任务上做任何事"）。

**余量提示**：健康臂 `deg` 实测 0.20–0.30（阶段 2 三代均为 0.20），阈值 0.40 的健康侧余量是 0.10，
死侧是 0.20–0.50。若后续任一健康臂出现 0.40，应把阈值上调到 0.45–0.50（并在 `loop.yaml` 注明依据），
而不是把该代改判为健康。
